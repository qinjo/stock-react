# 0003 — 基本面数据源与派生估值量

- **状态**：已采纳
- **日期**：2026-09-21
- **相关**：ADR-0001（行情数据源主备）、ADR-0002（提示词工程）、调研笔记 `_research/基本面数据接口调研笔记.md`（773 行，全部 curl 实测）

## 背景

提示词重构后，模型在每份报告里都把同一件事列为"最大盲区"：

> 「未提供历史估值分位，无法判断当前 PE 是历史底部还是新常态中枢」
> 「数据未提供盈利增速、现金流或行业景气度，无法判断低估值是价值洼地还是盈利预期下修」

即：**技术面数据喂得很足（12 项指标 + 250 根日 K），基本面几乎是空的**，模型只能在有数据的地方深挖。目标价连续三只股票留空，也是同一原因。

关键发现（实测）：**东方财富的反爬是按域名隔离的**。`push2.eastmoney.com`（行情）在封禁窗口返回 `HTTP 000` 时，`datacenter-web.eastmoney.com`（数据中心）**照常 200**，累计 20+ 次请求含 8 次并发零限流。

## 决策

### 1. 基本面数据源选 `datacenter-web`

- 免 key、CORS `*`、零限流，且与 push2 反爬互不影响 → **行情与基本面互不拖累**
- 财报：`RPT_F10_FINANCE_MAINFINADATA`（一次请求 8 期：营收/净利/同比/ROE/毛利率/净利率/负债率/EPS/BPS/每股经营现金流）
- 估值历史：`RPT_VALUEANALYSIS_DET`（日度 `PE_TTM`/`PB_MRQ`，分页 2×800 ≈ 6.4 年）
- 板块聚合：`RPT_VALUEANALYSIS_DET` + `filter=(BOARD_CODE=..)(TRADE_DATE=..)`（实测白酒Ⅱ 19 只）

### 2. 派生**估值分位**（回答"相对自身历史是高是低"）

由日度 PE/PB 序列计算近 3 年与近 5 年分位，规则：

- 只统计**正值**（亏损期的负 PE 无估值意义）
- 样本少于 30 个交易日则**拒绝给结论**（返回 null）
- 同时给出 min/median/max，让模型理解分布位置而不只是百分位

实测茅台：PE 17.61 处于近 3 年 **0% 分位**（区间 17.66–33.71）、PB 6.24 处于近 3 年 6.3% 分位——这是"五年未见"的估值水平，且是**可计算的事实**而非推测。

### 3. 派生**同业对比**（回答"相对同行业是贵是贱"）

行业 PE/PB 中位 + 个股在行业内的排名与溢价/折价。

**关键设计**：板块快照（同行业共享，TTL 1 小时缓存）与**个股相对位置**（溢价/排名）**分离计算**。若把整个对比对象一起缓存，不同个股会互相污染（拿到别人的溢价）。

实测发现该维度的价值极高：茅台「相对自身历史 0% 分位、相对同业 PB 溢价 172.5%」的**背离**，直接指向"市场在给板块盈利质量重新定价"的结论——这是单看任一维度都得不出的洞察。

### 4. 零外部数据的**隐含估值量**

仅用 PE(动)、PB、最新价、市值即可反推（`derived.ts`）：

| 派生量 | 公式 | 实测精度（vs 真实） |
|---|---|---|
| 隐含 ROE | `PB / PE` | 茅台 35.4%（实际约 35%） |
| 隐含 EPS | `价 / PE` | — |
| 隐含每股净资产 | `价 / PB` | — |
| 隐含净利润 | `市值 / PE` | — |

依据 ai-hedge-fund `features/snapshot.py`（派生聚合必须在代码里算好再喂，"让模型推理事实而不是重做算术"）。**这组量与财报实际值交叉验证后，能判断"低估值是错杀还是盈利下修"。**

### 5. 字段陷阱的规避（实测踩到，必须写进代码）

- `MLR` 是**毛利额（元）**不是毛利率，真毛利率是 `XSMLL`——本模块**不取 MLR**
- `JYXJLYYSR` 是小数比例且分母非总营收——本模块不取，避免歧义
- 财报是**年内累计（YTD）**口径，非单季（提示词中已注明）
- `filter` 语法为括号并置隐式 AND；同一接口族内 `SECUCODE`（带后缀）与 `SECURITY_CODE`（6 位）**混用**，用错报 9501/9201

## 后果

**收益**

- 分析从"推理出来的基本面"变成"有财报数据支撑的基本面"，并具备交叉验证能力
- 目标价由"一律 null"变为"有锚定值或专业拒绝"
- 独立端点 `/api/fundamentals`：选股即可查看，**不消耗 LLM 调用**
- 单票请求增加 2–3 次（财报 1 + 估值 2 + 板块 1），但全部落在零限流的 datacenter-web

**代价与限制**

- 分析 token 增加约 400–700（财报 6 期 + 分位 + 同业）
- 板块快照缓存 TTL 1 小时：行业估值日内变化有限，但跨日需失效（key 含交易日）
- 估值历史深度上限 **2018-01-02**，做不了近 10 年分位
- 北向资金**日度数据止于 2024-08-16**（个股只剩季度快照）→ 明确不让分析依赖"北向当日净流入"

**未采纳**

- `push2 stock/get` 的扩展基本面字段（f92/f100/f184 等）：调研时恰逢封禁窗口，**无法区分字段无效与被封**，故不采用未验证的路径
- 行业估值走 `push2 clist` 的 f9/f23：实测大面积返回 `"-"`
- 自建"历史价格 + 历史 EPS"拼接估值分位：`RPT_VALUEANALYSIS_DET` 直接给出日度序列，无需自算

**后续可扩展**（接口已验证、本轮未做）：两融数据（`RPTA_WEB_RZRQ_GGMX`，自带 3/5/10 日聚合）、业绩预告、股东户数、解禁批次。
