# 0005 — 热门榜（东财人气榜）数据层：一次性回填 + 每日冻结

- **状态**：已采纳
- **日期**：2026-11-11
- **相关**：调研 [`docs/research-hot-list-data.md`](../research-hot-list-data.md)（本文所有实测数字的唯一来源）；issue #32（数据层工单）、#31（回测 V1，宇宙定义）；ADR-0004（[全市场筛选器的数据层](0004-market-wide-screener-data.md)，本 ADR 对其中「严禁全市场抓取」做**有限度**放宽）；ADR-0001（[A 股数据源主备策略](0001-data-source-strategy.md)）

## 背景

`docs/spec.md:90` 把「回测」与「自行搭建数据仓储或全市场数据抓取」都列为 Out of Scope。ADR-0004 已为筛选器破例：建了本地日 K 库（`backend/data/kline.sqlite`），并把「全市场数据抓取」解禁但**严格限形**——只允许约 12–16 个请求/天的腾讯批量快照，**后端扇出轮询仍然严禁**（`docs/spec.md:100-103`）。

现在回测的宇宙定义是「近一个月内出现在热门列表、且期间有过涨停」的股票。本地库只有价量，**没有任何热度数据**（`hot_rank`/`人气`/`热榜` 全仓无命中），也没有任何当前快照可用于事后重建——所以必须新增一个数据层。

问题在于这个数据层的形状天生是「逐票」的：东财人气榜历史接口按 `code` 返回该票 366 天的每日名次，要重建「某日 Top-N 成员」，只能把全市场约 5,400 只各问一次。这在字面上就是 ADR-0004 明令禁止的扇出。

因此本 ADR 要回答的是：**把「一次性历史回填」和「筛选时逐票扇出」这两种行为明确区分开，前者在什么条件下允许，后者为什么仍然禁止。**

二者的差别不在请求数量，而在**频率与是否落盘**：

| | 一次性回填 | 筛选时逐票扇出 |
|---|---|---|
| 触发 | 人工执行一次（或断点续跑） | 每次用户请求 |
| 请求量 | 约 5,400 次，全生命周期一次 | 每次约 5,400 次，可无限重复 |
| 节奏 | 串行，间隔 ≥0.3 s | 与请求同频，无节制 |
| 产物 | 落本地 SQLite，之后**只读本地** | 不落盘，下次重爬 |
| 封禁暴露 | 有界、可观测、可中止 | 无界、不可控 |

后者仍然禁止：它把 IP 风险放大到与用户流量同阶，且不产生任何可复用资产。

## 决策

### 1. 数据源：东财人气榜历史 `getHisList`（唯一默认实现）

```http
POST https://emappdata.eastmoney.com/stockrank/getHisList
Content-Type: application/json
{"appId":"appId01","globalId":"786e4c21-70dc-435a-93bb-38",
 "marketType":"","srcSecurityCode":"SZ000665","yearType":"5"}
→ {"status":0,"data":[{"calcTime":"2026-11-11","rank":1493}, …]}
```

- 返回**逐票**每日 `rank`，`rank` 为**全市场位次**（观测约 5,000 量级），可直接与阈值比较。
- **366 行硬顶**：`yearType` 取 1/3/5 实测返回 182/366/366 行，区间恰为「今天 − 365 天 → 今天」，**含周末**。
- 免费、无需 key、无需 cookie。实测 3/3 成功（0.5 s 间隔）；`globalId`/`appId01` 为固定常量，**是否可缺省未验证**。
- **接口无公开文档**，解析必须容错；`rank` 缺失时**显式失败**，不得静默补 0（否则会凭空造出「排名第一」的成员）。

### 2. 表结构：随 `kline.sqlite` 一起落盘，版本升到 3

```sql
CREATE TABLE IF NOT EXISTS hot_rank (
  code TEXT    NOT NULL,
  date INTEGER NOT NULL,   -- YYYYMMDD，与 bars.date 同一口径
  rank INTEGER NOT NULL,   -- 全市场位次，缺失即不写行
  PRIMARY KEY (code, date)
) WITHOUT ROWID;
```

| 项 | 取值 | 依据 |
|---|---|---|
| 归属库 | `backend/data/kline.sqlite` | 与 `bars` 同库同事务语义，回测一次查询即可 join |
| `date` 键 | `INTEGER` `YYYYMMDD` | 沿用 `bars.date`；交易日历以 `trading_calendar` 为准，**不自己算周末** |
| 主键 | `(code, date)` + `WITHOUT ROWID` | 与 `bars`/`valuation` 一致，约 70 B/行量级 |
| `rank` | `INTEGER NOT NULL` | 缺行即"未 tracked"，不用 0/NULL 混淆语义 |
| `SCHEMA_VERSION` | `2` → `3` | `backend/src/market/store.ts:17` |
| 建表方式 | `CREATE TABLE IF NOT EXISTS` + 幂等 `migrate()` | **不建迁移目录**，沿用 ADR-0004 的既有风格（库是可再生产物，重跑 bootstrap 即可重建） |
| 版本库 | gitignore | 与 `backend/data/` 同为可再生构建产物 |

### 3. 回填脚本 `npm run backfill:hot-rank`：串行、限速、可续跑

- **串行，禁止并发**。这不是性能保守，是 ADR-0004 的封禁历史直接推论（见「风险与缓解」）。
- 请求间隔**默认 0.5 s，下限 0.3 s**，可由参数调高不可调低；全量约 **45 分钟–1 小时**。
- **按 `code` 断点续跑**：以「该 code 是否已有行」判定，已抓过的直接跳过；中断后重跑即续。
- 失败**指数退避**重试，重试耗尽则记下 code 并继续，最终汇总失败清单——不是整体失败。
- **只写本地库**，不回写任何缓存、不落中间文件、不发任何分析请求。
- 支持 `--limit N`：先跑 200 只小样本验证接口与解析，再放全量。
- 幂等：同 `(code, date)` 重复写入覆盖（`INSERT OR REPLACE`），重跑同一天不产生重复。

### 4. 每日冻结 `npm run update:hot-rank`：与 `update:kline` 同一批次

回填拿到的是「过去 365 天」，**一年后这 12 个月同样会滑出窗口并永久消失**。所以数据层必须同时具备「向后看一次」和「向前每天记一次」两半，否则今天回填的库会随日历推移自动缩水。

- 每个交易日抓**当日快照**，与 `update:kline` 放在同一批次执行；漏抓一天即产生一个不可恢复的洞。
- 快照只写当天：历史行不重写，保持"追加稳定"（与 ADR-0004 复权口径同一原则）。

### 5. 宇宙口径：`rank ≤ 100` + 滚动 **20 个交易日**

- 「在热门列表」判定为 `rank ≤ 100`。该阈值是本项目的**推断**（不是东财定义，接口只给位次不给"入榜"语义），标为「推断」，回测报告须注明。
- 滚动窗口 **20 个交易日**（不是自然日）：窗口内**出现过一次**即成员——这正是要按交易日对齐、并用 `trading_calendar` 而非日历减法的原因。
- 同一窗口内还须有过**涨停收盘**。涨停判定按「前收盘 ×(1±比例) 四舍五入到分」反推并与**不复权**真实价精确比对；比例由**板块**（主板 10% / 创业板·科创板 20% / 北交所 30%）与**当前名称是否 ST**（主板 5%）确定。
  不把 5% 作为主板普通股的候选，是因为那会产生成规模的假阳性（普通股收在 +5% 会被当成 ST 涨停）；
  代价是「当前非 ST、历史上曾戴帽」的主板股票，其历史 5% 板会被按 10% 漏判——库内无历史 ST 状态，这一点只能披露（见 issue #31、回测报告局限第 5 条）。
- 「出现过即成员」是**宽松口径**：它会纳入刚入榜又迅速掉出的票，使宇宙规模大于任何单日 Top-100 快照。

### 6. 窗口与结论边界：宇宙 A 与宇宙 C **不横向比较**

| | 宇宙 A（真实人气榜） | 宇宙 C（成交额 Top-100 代理） |
|---|---|---|
| 数据来源 | 本 ADR 的 `hot_rank` | 本地 `bars.amount` 排名 |
| 可回区间 | 约 **12 个月**（366 行硬顶） | 约 **6 年**（本地库全量区间） |
| 市场环境 | **单一** | 跨多轮周期 |
| 结论效力 | 样本内描述，**不可外推** | 可做跨周期稳健性 |

宇宙 A 的报告顶部必须写死「样本区间 2025-11 → 2026-11，单一市场环境，不外推」。**长窗口结论由宇宙 C 承担**；两者的收益数字**不放进同一张表横向比较**——那是把不同语料的数字当同一实验。

### 7. 付费路径不采纳为默认实现

tushare `ths_hot`/`dc_hot`（**6000 / 8000 积分**）与同花顺商业 API **不进默认流程**，仅作为东财被封时的退路记录在案。其中同花顺 `hot-stock-list-history` 是形状最正的替代（**逐日列表**，30 天窗口只需 30 次调用），但需商业 key 按次计费，且**同样只有一年上限**——付费并未换来更长历史。

## 后果

- **新增两个脚本**：`scripts/backfill-hot-rank.ts`（一次性）与 `scripts/update-hot-rank.ts`（每日），各配 `npm run backfill:hot-rank` / `update:hot-rank`。
- **新增一张表 + `SCHEMA_VERSION` 2 → 3**：老库打开时由幂等 `migrate()` 自动补表，无需手工迁移。
- **`docs/spec.md` 的 Out-of-Scope 措辞需同步修订**：在「全市场数据抓取」的解禁清单里加入「限速、串行、一次性落盘的人气榜历史回填」，并继续保留「筛选时逐票扇出严禁」。
- **测试永不触网**：用录制的真实响应做夹具，覆盖三个易错点——`rank` 缺失、周末行、断点续跑。任何测试不得依赖本机网络。
- **回测报告多一段边界说明**：「宇宙 A vs 宇宙 C」的口径、区间与不可比较性。
- **数据可复现性下降一格**：`hot_rank` 无法由公开 dump 重建（不像 `bars`），重跑 bootstrap 会**清空它**，必须重新回填。这是本数据层与既有库最大的性质差异。

## 风险与缓解

| 风险 | 依据 | 缓解 |
|---|---|---|
| **东财 IP 封禁** | ADR-0004 实测：突发 `clist?pz=6000` **0.083 s 即断**，ban #1 ≈ 4.3 分钟、ban #2 **≥10.2 分钟**且惩罚升级，并**蔓延到 `push2his`**；`emappdata` 是另一域名，本次实测未触发，但**没有任何证据表明它豁免** | 串行 + 间隔 ≥0.3 s；结果全部落盘，回测只读本地；按 code 可续跑；先跑 `--limit 200` 小样本确认行为，再放全量 |
| **接口无公开文档** | 接口来自前端抓包，`appId`/`globalId` 含义未知，无版本承诺 | 解析容错；`rank` 缺失显式失败不补 0；响应形状变化时脚本报错而非写脏数据 |
| **366 行硬顶，无长历史** | `yearType`=1/3/5 实测 182/366/366 | 放弃「>1 年人气史」的设想；长窗口由宇宙 C 承担 |
| **每日冻结漏跑不可逆** | 一日不抓即一日永久缺失 | 并入 `update:kline` 同一批次；回测前校验 `hot_rank` 的日期覆盖率 |
| **全量速率上限未做长跑压测** | 本次只测了 25–28 次请求 | 首次全量按最保守间隔执行并观察；出现连续失败立即中止而非重试硬扛 |
| **`rank` 分母不固定** | 每日被 tracked 的股票总数不明 | 阈值 100 视为推断；报告注明口径 |

## 开放问题（**未验证，待补测**，实现前补测或显式标注）

1. **北交所覆盖**：库内 598 只 `bj` 标的是否被该接口覆盖？`srcSecurityCode` 前缀是 `BJ…`、`8` 开头，还是别的？**待补测**。
2. **周末行语义**：366 行含周末，是「沿用前一交易日排名」还是「按自然日独立计算」？这决定回测能否直接按交易日 join。**待补测**。
3. **`rank` 缺失/停牌表示**：返回 `rank: 0`、缺行，还是别的？影响「当日 Top-N 成员」判定。**待补测**。
4. **每日 tracked 分母是否固定**：不固定则 `rank ≤ N` 跨日并非严格可比。**待补测**。
5. **长跑速率上限**：本次只测了 25–28 次请求，全量 5,400 次的真实上限未知。**待补测**。
6. **接口版本风险**：无公开文档的接口是否会在某次改版中变形状或下线。**无法补测，只能靠容错与显式失败兜住**。

## 替代方案对比

| 方案 | 历史 | 精度 | 成本 | 结论 |
|---|---|---|---|---|
| **东财 `getHisList`**（本决策） | 366 行 ≈ 12 个月 | 全市场真实位次 | 免费，~5,400 次请求 | **采纳**：唯一免费且够用的真实人气源 |
| tushare `ths_hot` / `dc_hot` | 约 2024 起，≈1 年 | 官方逐日 Top-N，形状最正 | **6000 / 8000 积分** | 退路：精度同档甚至更好，但要钱且仍 1 年上限 |
| 同花顺商业 API | 1 年 | 逐日列表 + 逐票趋势 | 商业 key 按次计费 | 退路：形状最贴合（30 天 30 次调用），但付费、同 1 年上限 |
| 东财龙虎榜 | **2015 起** | 中：机构/游资席位关注 | 免费、按日分页 | 不作主宇宙：每日仅 **20–90 只**，太稀疏 |
| 东财涨停股池 | 仅 t / t−1 | 高（最极端情绪） | 免费 | 不可用于回测：历史探针全 `tc:0` |
| 成交额排名（`bars.amount`） | **6 年** | 低：无热度语义 | 零成本 | 采纳为**宇宙 C**：长窗口结论由它承担，与 A 不横向比较 |
