# A股智能分析 MVP —— 功能规格

> 状态：`ready-for-agent` — 已发布为 GitHub issue [#1](https://github.com/qinjo/stock-react/issues/1)（qinjo/stock-react）
> 依据：本轮设计树（grilling）共识 + 两份调研笔记（[开源LLM金融分析项目调研笔记](../_research/开源LLM金融分析项目调研笔记.md)、[free-stock-api-research.md](../free-stock-api-research.md)）。

## Problem Statement

用户想从零学习并构建一个「A 股智能分析」小工具：在界面上输入股票代码或名称，系统通过免费接口获取行情与历史数据，交大模型生成结构化投资分析（评级、置信度、目标价、风险点与结论报告），并用信号卡 + 报告 + K 线图展示。当前一切皆无：仓库为空、无代码、无数据管线、无提示词、无 UI。用户同时希望借该项目走通「前端 → 后端 → 外部数据 → 大模型」的全链路，并以提示词工程为学习亮点。

## Solution

一个浏览器访问的 Web 应用：前端（React + Vite + TS + Tailwind + KLineChart）提供搜索框（代码或中文名补全）与结果页；后端（Node + Fastify + TS）承担全部外部请求——东方财富免 key 数据代理（实时快照 + 日 K + suggest 名称搜索）、派生指标计算（technicalindicators）、DeepSeek（`deepseek-chat`）单次调用分析、响应解析与内存缓存。用户查询一只 A 股股票，数秒内得到：5 档评级信号卡（含置信度、可选目标价/时间窗、一句话理由）、五节分析报告（快照→基本面→技术面→风险清单→结论），以及一张 K 线走势图。后端缓存同票 10 分钟；异常按约定契约展示（数据不足 abstain / 分析失败重试一次 / 数据源不可用提示），并全程展示免责声明。

## User Stories

1. 作为用户，我想输入 6 位 A 股代码（如 `600519`）或名称（如 `茅台`）来发起查询，以便快速定位目标股票。
2. 作为用户，我想输入 `sh600519`、`600519.SH` 等带前缀格式也被宽容识别，以便不必记忆严格格式。
3. 作为用户，我想在输入中文名/代码片段时看到下拉补全候选（含代码与名称），以便减少输入与拼写错误。
4. 作为用户，我想看到查询过程中的加载状态（取数中/分析中），以便了解系统在做什么而非空白等待。
5. 作为用户，我想看到股票身份事实快照（代码、名称、行业、实时价、涨跌幅、市值、PE、PB、换手率），以便核实数据口径。
6. 作为用户，我想看到明确标注的「数据截至日期」（行情日期与最近财报披露日），以便知道信息的时效边界。
7. 作为用户，我想看到 5 档评级结果（买入/增持/持有/减持/卖出）与 0-100 置信度，以便快速获得结论性判断。
8. 作为用户，我想看到模型给出的一句话理由（reasoning），以便在不读全文时先抓住核心逻辑。
9. 作为用户，我想看到可选的目标价与时间窗（可为空，空表示模型无把握），以便理解分析与操作建议的距离。
10. 作为用户，我想阅读五节分析报告（快照/基本面/技术面/风险清单/结论），以便深入理解评级依据。
11. 作为用户，我想看到风险点以清单形式单列，以便快速核查下行风险。
12. 作为用户，我想看到一张 K 线走势图（可缩放/十字光标），以便直观感知价格形态。
13. 作为用户，我想在数据不足（如上市过短）时看到明确的「数据不足，无法分析」而非强行给结论，以便不被误导。
14. 作为用户，我想在分析失败时看到「分析失败」提示并可重试，以便区分「失败」与「看空」。
15. 作为用户，我想在数据源不可用时看到「数据源暂时不可用」提示，以便理解超时/断连原因。
16. 作为用户，我想重复查询同一只股票时获得即时缓存响应（10 分钟内），以便节省时间与调用成本。
17. 作为用户，我想看到页面上明确的「AI 生成内容不构成投资建议」免责声明，以便知悉内容性质。
18. 作为用户，我想在分析报告中看到报告为中文输出，以便阅读顺畅。
19. 作为开发者，我想让所有外部请求（东财、DeepSeek）只发生在后端，以便 API key 永不落入前端。
20. 作为开发者，我想让派生指标（SMA/RSI/MACD/ATR/波动率等）由后端代码计算而非模型计算，以便消除算术幻觉。
21. 作为开发者，我想让 LLM 输出遵循固定 JSON 契约并带三级解析回退，以便抵抗杂散文本与空值字符串。
22. 作为开发者，我想让「数据不足 / LLM 失败」显式 abstain 而非静默变中性，以便信号语义不被污染。
23. 作为开发者，我想让提示词包含点时间硬规则（把最近披露日当今天、只用给定数据、不发明数字），以便遏制事后诸葛型幻觉。
24. 作为开发者，我想让同一只股票的重复分析命中提示词缓存（数据无变化不重复调用），以便控制成本（约 ¥0.02–0.05/次）。
25. 作为开发者，我想让缓存 TTL 与内存存储可配置，以便部署时调整行为。
26. 作为学习者，我想看到项目附带架构/流程说明（README 或注释），以便理解全链路各层职责。
27. 作为学习者，我想在源码中看到提示词模板独立成模块且注释解释六段结构，以便专注学习提示词工程。
28. 作为学习者，我想让数据适配层隔离东财字段细节，以便未来扩展美股时只动适配器不动上层。
29. 作为部署者，我想让后端限流（简单按 IP）在公开部署时可启用，以便防止免费数据源/LLM 被滥用。
30. 作为维护者，我想让两个核心纯函数模块（适配器归一化、分析流水线）有单测覆盖，以便重构时有安全网。

## Implementation Decisions

- **总体架构**：前后端分离的单一仓库。React+Vite+TS 前端；Node+Fastify+TS 后端。数据全走后端代理，浏览器不直连东财或 DeepSeek。
- **模块划分（职责边界，不含文件路径）**：
  - *东财数据适配器*：将东财实时快照（`push2 …/stock/get`）、日 K（`push2his …/kline/get`、`klt=101`、`fqt=1` 前复权）、名称搜索（`suggest` 接口）响应归一化为领域模型。处理：`f43` 等字段 ×100 缩放（或请求 `fltt=2`）、K 线 11 列序（date, open, close, high, low, volume, amount, 振幅, 涨跌幅, 涨跌额, 换手率）、secid 判定（沪 `1.` / 深 `0.`）。
  - *派生指标计算*：基于日 K 以 `technicalindicators` 库计算 SMA50/200、RSI、MACD(DIF/DEA/HIST)、ATR、区间涨跌幅、波动率等 ~12 个指标，代码算好喂模型。
  - *提示词构造器*：采用 ai-hedge-fund 六段 persona 模板（角色定位 → 清单式思维链 → 信号规则 → 置信度 4 档锚定 → 硬规则（点时间约束/只用给定数据/不发明数字/数据不足 abstain）→ JSON-only 输出）。一次调用内分段模拟多角色（快照核对、基本面、技术面、风险、结论）。报告分节：①公司与数据快照 ②基本面评估 ③技术面评估 ④风险点清单 ⑤结论与目标区间。输出语言中文（按需追加语言指令）。
  - *LLM 客户端*：对接 DeepSeek `deepseek-chat`，key 从服务端环境变量读取；使用 JSON 输出模式 + 固定输出契约；失败/解析失败 → 重试一次 → abstain。
  - *LLM 响应解析器*：三级回退（```json fence → 整串 → 首个平衡 `{}`块），空值字符串（"None"/"N/A"/"-"）转 null；校验 signal ∈ 5 档枚举、confidence ∈ [0,100]。
  - *分析服务（主缝合点）*：编排快照+指标+K 线截尾（60 根）→ 提示词 → 调用 → 解析 → 类型化 `AnalysisResult`；带内存缓存（TTL 10 分钟，键含 secid 与数据指纹）与提示词哈希缓存。
  - *API 契约（后端端点）*：`GET /api/search?q=`（名称/代码补全）；`GET /api/analyze?code=`（完整分析，含缓存）；错误统一 JSON 形状（`{status, code, message}`）区分 数据不足 / 分析失败 / 数据源不可用。
  - *前端*：搜索框（防抖 + 补全下拉）→ 结果视图状态机（loading / success / abstain / failed / source-unavailable）→ 信号卡（评级徽章 + 置信度条 + reasoning + 可选 target/horizon）+ 五节报告渲染 + KLineChart 走势图 + 免责声明。纯 React hooks 状态管理，Tailwind 样式。
  - *LLM 输出契约（一次调用返回）*：
    - `{ rating: "buy"|"overweight"|"hold"|"underweight"|"sell", confidence: 0-100, reasoning: string, price_target: number|null, time_horizon: string|null, sections: { snapshot, fundamentals, technicals, risks, conclusion } }`
    - 数据不足场景允许返回明确 abstain 标志而非强行评级。
- **成本与性能预算**：单次分析约 3000–4700 token（快照+~12 指标+60 根 K 线+模板+输出），成本约 ¥0.02–0.05；缓存后重复查询零 LLM 调用。
- **合规与安全**：UI 常驻免责声明；key 仅存服务端 `.env`；公开部署时启用按 IP 的简单限流中间件（可配置开关）。

## Testing Decisions

- **好测试的标准**：只测外部行为（给定输入 → 断言输出/契约），不测实现细节；所有测试永不触网（fake LLM、录制 fixture）。
- **测试模块**：① 分析流水线（主 seam）：注入 fake LLM 四种夹具（干净 JSON / 杂散文本需三级回退 / 空值字符串 / 抛错）断言解析、abstain、重试与评级枚举校验；② 东财适配器（次 seam）：用调研笔记中已实测录制的真实响应 fixture 断言缩放、列序、secid 归一化。
- **先例**：绿地项目无既有测试先例；fixture 数据以 `free-stock-api-research.md` 实测样例为权威来源。

## Out of Scope

- 美股及任何非 A 股市场（仅预留适配器扩展点）。
- 多股对比、自选/持仓管理、历史分析记录、定时任务。
- 新闻/社交情绪等外部情绪数据源（免费源不可得，情绪仅以换手/量价间接表达）。
- 回测、实盘交易、资金管理、任何交易执行能力。
- 用户系统、数据库持久化（缓存仅内存）、移动端适配。
- 自行搭建数据仓储或全市场数据抓取（避免东财反爬风险）。
