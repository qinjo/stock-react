- **相关**：issue #26（人工验收）、参数表 [`screener-params.md`](screener-params.md)
- **复现**：`npm run profile:rules`（可加 `--mode event --strictness strict`）

## 为什么单独做这一份

漏斗只告诉你"从 5555 到 243"，**不告诉你谁拦的**。前面十四轮验证的都是
"规则是否按声明的条件判断"，但**没有一轮验证过"它在真实数据上到底起没起作用"**——
一个从不触发的规则可能是死重量、也可能是阈值写错了；一个拦下 57% 的规则值得复核是否过激。

## 关键修正：上表的口径是错的，必须看"走到了多少只"

规则是**分层短路**的：后段规则只面对通过了前置规则的少数标的。
拿"拦下数 / 全市场"去读，会把**分母小**误读成**阈值松**。

按"走到了多少只"重算（这是判断阈值松紧的正确口径）：

| 规则 | 走到 | 拦下 | **拒绝率** |
|---|---:|---:|---:|
| `U-ma100` 站上 MA100 | 4855 | 3191 | **65.7%** |
| `U-turnover` 成交额下限 | 975 | 510 | **52.3%** |
| `U-marketCap` 流通市值区间 | 1664 | 689 | **41.4%** |
| `U-growthIndexGate` | 380 | 105 | 27.6% |
| `X-ma100Whipsaw` | 465 | 85 | 18.3% |
| `U-aboveTrendline` 不在下降趋势线之下 | 275 | 28 | **10.2%** |
| `U-notRange` 震荡区间内部 | 247 | 4 | **1.6%** |
| `E-st` | 5207 | 193 | 3.7% |
| `E-live` | 5428 | 221 | 4.1% |
| …（其余见文档末尾） | | | |

链条自洽可验：`4855 →（U-marketCap）1664 →（U-turnover）975 →（X-ma100Whipsaw）465
→（U-growthIndexGate）380 →（U-aboveTrendline）275 →（U-notRange）247 → 243`。

**我上一版写"书里的结构类规则合起来不到 2%"是错的**——那正是错误分母造成的。
按正确口径，`U-aboveTrendline` 一个人就拒绝 **10.2%**，是个在正常工作的筛子；
`U-notRange` 确实只有 **1.6%**，但那是**形态在 MA100 幸存者里本就罕见**
（第 14 轮加的"净位移占比"判别式会把多数窄区间判成"推进中"而放行），不是阈值太松。

**三条结论：**

1. **漏斗由一条规则主导**：`U-ma100` 拒绝 65.7%。这符合书的原意
   （"通常只买入价格运行在 MA100 均线之上的股票"），但也意味着**筛选器一半以上的选择权
   压在这一条上**——它若错了，整套结果就错了。这也是为什么它的引文（L597）值得反复核。
2. **两条"书外/推断"的门槛在幸存者里做了大量淘汰**：成交额拒绝 52.3%、市值拒绝 41.4%。
   也就是说，书的规则先把池子缩到 4855，**之后主要由我们自己定的流动性与市值门槛
   把它再砍到 243**。界面按 `书/推断/书外` 三级标注来源，正是为了让这件事可见——
   否则用户会以为结果全是那本书挑的。
3. **结构类规则并非"从不生效"**：趋势线 10.2%，只是它们只面对已经通过均线分界线的标的，
   所以绝对数看起来小。

## 适用却「从未拦下任何一只」的三条——逐条核实

**画像里出现"从不触发"时，第一反应应当是怀疑探针，而不是相信它。**
第一版探针就假出了三条（没传大盘门 → `U-growthIndexGate` 一律走"数据缺失"；
用了趋势模式 → 三条事件模式规则被跳过；loader 已按板块过滤 → `E-board` 不可能触发）。
修掉这些假象后，剩下的三条各有明确原因：

| 规则 | 为什么从不触发 | 判定 |
|---|---|---|
| `E-suspended` 剔除停牌 | **全库 734 万行里 `volume = 0` 有 0 行**。条件 `last.volume > 0` 恒真 | **数据决定**，见下 |
| `E-board` 板块开关 | 适配层已按板块过滤，规则是第二道防线 | 设计如此 |
| `U-trendR2` 走势流畅度 | 只有严格档设了阈值（0.7），标准档为 `null` | 设计如此 |

### 关于 `E-suspended`：不是死代码，是数据决定的

它的条件是"最后一根成交量 > 0 才通过"。实测**全库没有任何一根日线的成交量为 0**
（写入路径也保证了这一点：`planDailyBar` 会跳过无成交量的快照）。
所以它在这份数据上**永远无法触发**。

保留它的理由：数据来自第三方社区 dump，未来版本有可能带上零成交量行；
而且它是廉价的不变式检查。**但必须知道它在当前语料上是空转的**——
否则会误以为"停牌股由它把关"，实际上把关的是 `E-suspended-today`（拦下 3 只）
与写入路径本身。
