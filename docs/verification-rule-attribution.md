# 规则归因画像（真实数据，2026-09-30）

- **相关**：issue #26（人工验收）、参数表 [`screener-params.md`](screener-params.md)
- **复现**：`npm run profile:rules`（可加 `--mode event --strictness strict`）

## 为什么单独做这一份

漏斗只告诉你"从 5555 到 243"，**不告诉你谁拦的**。前面十四轮验证的都是
"规则是否按声明的条件判断"，但**没有一轮验证过"它在真实数据上到底起没起作用"**——
一个从不触发的规则可能是死重量、也可能是阈值写错了；一个拦下 57% 的规则值得复核是否过激。

## 实测（趋势模式 · 标准档 · 大盘门 empty）

**全市场 5555 只（非北交所）→ 通过基础池 243 只（4.4%）**

| 规则 | 拦下 | 占比 | 说明 |
|---|---:|---:|---|

| `U-marketCap` 流通市值区间 | 689 | 12.4% | 推断参数，20–80 亿 |
| `U-turnover` 成交额下限 | 510 | 9.2% | 书外补丁，5000 万 |

**两条结论：**

1. **漏斗由一条规则主导**：`U-ma100` 一个人拦下 57.4%。这符合书的原意
   （"通常只买入价格运行在 MA100 均线之上的股票"），但也意味着**筛选器一半以上的选择权
   压在这一条上**——它若错了，整套结果就错了。这也是为什么它的引文（L597）值得反复核。
2. **推断参数的拦截量远超书内规则**：市值 12.4% + 成交额 9.2% = 21.6%，
   而书里的结构类规则（震荡 0.1% + 趋势线 0.5% + 123 等）合起来不到 2%。
   界面按 `书/推断/书外` 三级标注来源，正是为了让这件事可见。

## 适用却「从未拦下任何一只」的三条——逐条核实

**画像里出现"从不触发"时，第一反应应当是怀疑探针，而不是相信它。**
第一版探针就假出了三条（没传大盘门 → `U-growthIndexGate` 一律走"数据缺失"；
用了趋势模式 → 三条事件模式规则被跳过；loader 已按板块过滤 → `E-board` 不可能触发）。
修掉这些假象后，剩下的三条各有明确原因：

| 规则 | 为什么从不触发 | 判定 |
|---|---|---|
| `E-suspended` 剔除停牌 | **全库 734 万行里 `volume = 0` 有 0 行**。条件 `last.volume > 0` 恒真 | **数据决定**，见下 |
| `E-board` 板块开关 | 适配层已按板块过滤，规则是第二道防线 | 设计如此 |
| `U-trendR2` 走势流畅度 | 只有严格档设了阈值（0.7），标准档为 `null` | 设计如此 |

### 关于 `E-suspended`：不是死代码，是数据决定的

它的条件是"最后一根成交量 > 0 才通过"。实测**全库没有任何一根日线的成交量为 0**
（写入路径也保证了这一点：`planDailyBar` 会跳过无成交量的快照）。
所以它在这份数据上**永远无法触发**。

保留它的理由：数据来自第三方社区 dump，未来版本有可能带上零成交量行；
而且它是廉价的不变式检查。**但必须知道它在当前语料上是空转的**——
否则会误以为"停牌股由它把关"，实际上把关的是 `E-suspended-today`（拦下 3 只）
与写入路径本身。
