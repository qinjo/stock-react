## 为什么有这份文件

筛选器的验证做了十五轮，方法散落在十几条提交信息里。**单个修复会过期，方法不会**——
这份文件把"哪种手段能找出哪一类缺陷、以及它自己会怎么骗你"归并到一处，
给下一个维护者（或下一个 agent）用。

一条贯穿始终的经验：**真实数据与真实网络能找到的东西，假夹具与单测在结构上就找不到。**
下面每一类都附了实例，也附了它自己的失效模式——包括我自己犯过的错。

## 一、静态契约比对

**做法**：把两侧的类型定义读出来逐字段/逐取值比对（`backend/test/contract-types.test.ts`）。

**找到了什么**：前端 `SignalId` 少了事件模式的五个 id（S6/S7/S9/S10/S12）——
接口在 `mode=event` 下返回的正是它们。界面只显示 `label` 所以没炸，
但**那个类型在说谎**：任何 `switch (id)` 都会把事件分支当成不可达。

**失效模式**：解析器误报。同一轮里我两次误判——
把文档注释里的中文字符串当成了联合类型的取值；
`export type Rating = (typeof RATINGS)[number]` 这种写法取值在常量数组里、
且常量名与类型名不同。**先剥注释、再顺着 `typeof` 找常量**，误报才消失。

## 二、标签扫描（无需覆盖率工具）

**做法**：覆盖率包装不上（npm 缓存目录权限坏了），于是换个等价做法——
把代码产出的**可观察标签**（跳过原因、错误码、规则文案、提示语）全列出来，
逐个查测试有没有断言过。

**找到了什么**：
- `unknown-symbol` 分支**从未被任何测试走到**（真实场景：新上市的票先出现在快照里）
- `NOT_FOUND` 在前后端错误码里都声明了，但**后端从不抛、前端也无分支**——纯死表面
- `E-st` 在名称为空时的处置没有断言（而真实库里确实有 3 只这种标的）

**失效模式（重要）**：**它分不清两件事**——
"分支根本没走到"（强发现）与"走到了但只断言了布尔值、没断言散文"（弱发现）。
第一轮扫描出的 29 条里绝大多数是后者。**逐条断言散文是脆弱且低价值的**，
所以不要为了凑覆盖率去写它们。

## 三、阈值边界与"报数真实性"

**做法**：直接调规则本身（不穿整条引擎），在每个阈值两侧各断言一次；
并把说明里报出的数与实际参与比较的数逐一对照。

**找到了什么**：结论全部正确——但**测试的价值在于把它钉住**：
`stopSpaceMax` 是"上限本身可用"、`ma100CrossMax` 是"达到即排除"、
市值区间两端都含等号。这些"含不含等号"改一位不会报错，只会让候选悄悄多一只或少一只。

**失效模式（我犯过三次）**：
- 用 `MA100` 里的 "100" 当成数字，三元组全错位 → 解析前先剥掉 `MA\d+`
- 把「近 N 日穿越 MA X 次 < 上限」按两个数解构，实际是三个
- 连板规则的夹具没有先造出涨停，而该规则在"当日未涨停"时提前返回

**共同教训**：**失败的第一次，先怀疑量具，再怀疑被测对象。**

## 四、真实数据画像

**做法**：在全市场真实数据上跑一遍，统计**每条规则拦下了谁**（`npm run profile:rules`），
以及各类取值的真实分布。

**找到了什么**：
- `U-ma100` 一条拒绝 **65.7%**，主导整个漏斗
- 被市值闸门拒的 689 只里 **75% 是因为高于上限**（而那个上限完全由我们构造）
- **两条"书外/推断"门槛（成交额 52.3% + 市值 41.4%）在 MA100 幸存者里做了大部分淘汰**
- 真实库里有 3 只在市股票**名称为空**（快照日停牌 → 名称没补上）
- `E-suspended` **在当前语料上永远无法触发**（全库 734 万行里没有一根零成交量日线）

**失效模式（我犯过两次，都很隐蔽）**：
- **错误分母**：规则是分层短路的，后段规则只面对通过了前置规则的少数标的。
  我第一版按"拦下数 / 全市场"读，得出"书内结构类规则几乎不生效"的**错结论**；
  改成"拦下数 / 走到了多少只"后，`U-aboveTrendline` 其实是 **10.2%**，正常工作的筛子。
- **复权算重**：我自己另算 MA100 偏离度时把因子乘了两遍，得到一份
  "各档合计 4714 只线下、却只有 3191 只被拒"的**自相矛盾**分布。

### 防御手段：先检查数字内部是否自洽

上面两次都是靠**内部对不上**才发现的（子项之和 ≠ 总数、线上 + 线下 ≠ 到达数）。
所以做任何真实数据统计，**先算一个能把子项与总数对上的校验**，
对不上就说明口径错了——不要带着一个漂亮的图去下结论。

## 五、真实网络与真实模型

**做法**：真跑一次增量；真跑一次模型（`npm run verify:llm`）。

**找到了什么**：
- **增量在同一交易日内完全幂等**（12 项指纹含复权因子之和，一项未变）
- 同日重跑时输出**误导文案**："中间缺口无法用当日快照补齐"——根本没有缺口
- `bootstrap` 的顺序是对的（下载 + 校验在删库之前），但**中断会留下半成品库**，
  而那种库**用起来毫无异常**（已加守卫）
- 大模型两条路径**一次通过**：复核输出能被解析、确实按档内排序、
  短线视角确实不给目标价

**失效模式**：慢、要网络、要密钥；模型输出会随版本漂移，
**所以它属于手动验证脚本，不属于测试套件**（测试铁律是"永不触网"）。

## 六、我自己的测量错误清单（三次）

| 轮次 | 错误 | 后果 | 怎么发现的 |
|---|---|---|---|
| 44–45 | **错误分母**（拦下数 / 全市场） | 得出"书内规则几乎不生效"的**错结论**并写进文档 | 写下一轮时重算拒绝率，发现口径本身不成立 |
| 47 | **复权算重** | 一份自相矛盾的偏离度分布 | 各档合计 ≠ 被拒总数 |
| 50 | Python 中文引号 | 注释没写进去，**提交信息成了假陈述** | 下一轮 grep 复查时发现注释不存在 |

**共同点：三次都是"结论先于核对"。** 所以：
1. 任何统计先算一个自洽校验（子项 vs 总数）
2. 提交信息里写的每句话都当场核实（第 42 轮我把"后端 526 项"写成了一个实测 525 的数字，
   也是同一类问题）
3. 中文引号别放进双引号字符串（我栽了三次）——用「」

## 七、已验证 / 已否决 / 只能靠人的清单

**已自动化的守卫**

| 手段 | 覆盖 |
|---|---|
| `npm test`（后端 535 / 前端 128） | 全部单测；永不触网 |
| `npm run verify:invariants` | 10 项数据不变式，跑在 730 万行真实库上 |
| `backend/test/contract-types.test.ts` | 前后端类型契约（含自检） |
| `npm run verify:kline` | VWAP 恒等式 + 与外部行情交叉校验 |
| `noUnusedLocals`（两侧 tsconfig） | 死代码门禁 |

**已明确否决的检查**

- **日线不得有缺日**：实测 28% 的标的"不满足"，但那是**停牌**。
  分布是平滑重尾（缺 1 天 340 只 / >100 天 19 只），且**丢一次增量留下的空洞
  与停牌在数据上无法区分**——这条检查必然产生 28% 假阳性。
  记录在 `scripts/verify-invariants.ts` 的注释里。

**只能靠人的一层**

把书里的定性描述翻成具体数字是否**合理**（"刚刚突破" → 10 个交易日、
"大幅快速回调" → 15%/30 日……）。引文准确性已穷尽核对（30/30），
代码内部一致性已多重核对，**剩下的要验的是"翻译得好不好"，不是"翻译得对不对"**。
入口：`docs/verification-replay-2026-09-29.md` 文末清单。
