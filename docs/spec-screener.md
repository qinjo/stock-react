# A股短线筛选器 —— 功能规格

> 状态：**待实现**（本轮 grilling 共识 + 电子书规则提炼；参数表待用户审阅）
> 依据：`_research/短线操盘技法-选股规则提炼.md`（1,013 行 / 162 处带行号原文引用，A 类「书中明确」与 B 类「推断」严格分离）、`_research/短线操盘技法-选股规则提炼.md` 引用的全文提取稿、以及三轮实测调研（全市场快照可行性、Qlib dump 可用性、bootstrap 数据源）。
> 源书：老牛《短线操盘实战技法》（民主与建设出版社，ISBN 9787513926188）。**该书不是指标阈值手册**——作者明确弃用 KDJ/RSI/布林线，原话「根本就不研究成交量」。全书真正的数值只有**均线参数**与**结构位置**。
> 关联：本规格修订 `docs/spec.md` 的 Out of Scope，并新增 ADR-0004。

## Problem Statement

用户已有一个「A股智能分析」工具：输入单只股票的代码或名称，得到行情快照、日K、派生指标、基本面与一份 AI 五节报告。它能回答**「这只股票怎么样」**，但完全无法回答**「今天该看哪几只」**——用户必须自己先想出一个代码才能开始。

用户手上有一本讲 A 股短线操盘的书（《短线操盘实战技法》），书中给了一套具体的、可执行的选股与操盘方法（站上 MA100 选股、MA20 上穿入场、低位 123 结构、突破性缺口与涨停、大参数入场/小参数止损配对、按大盘位置决定仓位）。但这套方法要求**在五千多只股票上同时做筛选**，人工逐只翻 K 线不可行。

同时，任何"全市场扫描"都撞上项目现有的两条硬约束：`docs/spec.md` 把"自行搭建数据仓储或全市场数据抓取"明确列为 Out of Scope，ADR-0001 写明东财有 IP 级反爬并**「严禁后端扇出轮询」**。所以用户面临的真实问题不只是"加个筛选器"，而是**在不触发数据源封禁的前提下，让一本书的规则真的跑在全市场上**。

## Solution

在现有应用顶部增加一个「**短线筛选器**」模式（与「单票分析」并列，不引入路由）。用户在两种模式（**均线跟随** / **事件驱动**）与三档严格度（**宽松 / 标准 / 严格**）之间选择，点一次「开始筛选」，数秒内得到**至多 10 只**候选股——数量不可调，因为粒度就是"供我逐一选择"。

每只候选股给出：命中的规则清单（规则名 + 阈值 + 该股实际值 + `书 L####` 或 `书外` 来源标记）、扣分项、**离场条件**（止损位及其依据、信号失效条件、分批止盈规则）、**参考压力位**、建议仓位，以及一句话理由。**不给目标价**——书的逻辑是"跟随趋势直到结构破坏"，而不是"到价卖出"。

结果页同时给出**大盘门状态**（进攻/防守/空仓）与据此推出的**今日建议总仓位**，并**直接披露作者自述的历史胜率（牛市≈50%、熊市≈30%）与「空仓时间应长于持仓时间」**——因为在熊市里筛不出票本身就是这套方法的正确输出。

支撑这一切的是一个**本地日K库**：一次性从社区 Qlib dump bootstrap 全市场六年日线（含复权因子），此后每日用约 12 个腾讯批量快照请求增量更新，指标全部在本地计算。**全市场扫描零逐票扇出**，从结构上规避反爬。规则命中与排序由确定性代码完成；大模型只在同一信号档内做复核排序与写理由，且它失败时功能照常可用。

## User Stories

### 入口与模式
1. 作为用户，我想在顶部切换到「短线筛选器」模式，以便不离开当前应用就能从单票分析转到全市场选股。
2. 作为用户，我想点某个候选股后切回「单票分析」并自动载入该股，以便立刻看它的行情快照、K 线与 AI 报告。
3. 作为用户，我想在「均线跟随」与「事件驱动」两种模式间选择，以便分别按书里的均线体系与缺口/涨停事件体系选股。
4. 作为用户，我想在三档严格度间选择，以便在市场清淡导致候选不足时放宽、在想要精选时收紧。
5. 作为用户，我想有科创板开关与是否纳入北交所的开关，以便按自己的交易权限与风险偏好限定股票池。
6. 作为用户，我想每次最多返回 10 只且数量不可调，以便结果始终是我能看完并逐一决策的粒度。
7. 作为用户，我想切换模式或严格度时旧结果立即作废并重跑，以便不会把两组不同参数的结果混着看。

### 结果契约
8. 作为用户，我想候选不足 10 只时如实返回实际数量（可为 0），以便不被凑数的候选误导。
9. 作为用户，我想在 0 只时看到「今日无符合条件个股」并明确区别于「数据源不可用」，以便区分"没有机会"与"系统坏了"。
10. 作为用户，我想一键放宽严格度重跑，以便不用手改一堆参数就能看到更宽的结果。
11. 作为用户，我想每条候选可展开看到命中的规则清单（规则名 + 阈值 + 该股实际值），以便验证它为什么被选中。
12. 作为用户，我想每条规则标注 `书 L####` 或 `书外` 来源，以便区分"电子书里的技法"与"系统自己加的补丁"。
13. 作为用户，我想看到扣分项与未满足项，以便知道这只票的弱点在哪。
14. 作为用户，我想在页头看到漏斗计数（全市场 → 排除池 → 硬门槛 → 入围 → 复核），以便诊断"今天为什么只有 3 只"。
15. 作为用户，我想每条候选给出止损位及其依据（低点 3 / 均线配对 / 固定比例），以便知道错了在哪走。
16. 作为用户，我想每条候选给出信号失效条件（如缺口 3 日内回补），以便知道什么情况下该放弃这笔交易。
17. 作为用户，我想每条候选给出参考压力位（前高 / 缺口上沿 / 震荡区间上沿），以便有减仓的参照。
18. 作为用户，我想系统**不输出"目标价"这个词**，以便我不会误以为它在预测涨幅。
19. 作为用户，我想每条候选给出建议仓位，以便不用自己换算该下多少。
20. 作为用户，我想结果按**信号档**排序而不是 1–100 评分，以便不需要相信任何无法溯源的权重。

### 大盘门
21. 作为用户，我想看到大盘门当前处于进攻/防守/空仓哪一档，以便理解今天该不该出手。
22. 作为用户，我想在「空仓档」默认不出票并看到空仓横幅，以便在逆风时不被诱导交易。
23. 作为用户，我想能覆盖大盘门（逃生开关）并看到"正在违反书的择时前提"的明确提示，以便在明知风险时仍保有选择权。
24. 作为用户，我想结果页给出「今日建议总仓位」，以便把个股选择与仓位纪律一起拿到。
25. 作为用户，我想做创业板股时额外考虑创业板指与 MA100 的关系，以便遵守书里对创业板活跃度的判断。

### 数据与新鲜度
26. 作为用户，我想看到「数据截至 YYYY-MM-DD」，以便知道结果的时效边界。
27. 作为用户，我想点「开始筛选」时若本地库落后就自动补当日数据并显示进度，以便不需要记得先手动更新数据。
28. 作为用户，我想能强制刷新绕过当日缓存，以便盘中数据变化后手动重跑。
29. 作为用户，我想同一天同一参数的重复筛选命中缓存，以便重复点击不产生额外请求与等待。
30. 作为用户，我想在本地库尚未初始化时看到明确的「数据未就绪，请先运行 bootstrap」提示，以便知道该做什么而不是看到一堆空结果。

### 大模型边界
31. 作为用户，我想每条候选上有「深度分析」按钮按需触发，以便不为 10 只票一次性付出 10 次大模型调用。
32. 作为用户，我想深度报告使用**短线操盘视角**（MA100 位置 / 123 结构 / 离场条件 / 仓位，不出目标价），以便它和筛选器说的是同一套语言。
33. 作为用户，我想在大模型不可用时仍能看到规则引擎的结果与排序，并看到「未经 AI 复核」标注，以便模型故障不会让整个功能失效。
34. 作为用户，我想大模型只在同一信号档内复核排序与写理由、不得引入新候选，以便结果来源可追溯。

### 合规与预期管理
35. 作为用户，我想每张候选卡片常驻「规则/AI 生成，非投资建议」小标，以便不会把它当成荐股。
36. 作为用户，我想页脚明确「不构成买卖要约」与「未经基本面与合规审查」，以便清楚内容性质。
37. 作为用户，我想结果页直接显示作者自述的历史胜率（牛市≈50%、熊市≈30%）与「空仓时间应长于持仓时间」，以便对这套方法的期望是合理的。

### 学习
38. 作为学习者，我想看到每条规则的阈值与实际值对照，以便借此学会这套短线技法的判据。
39. 作为学习者，我想看到漏斗各档的淘汰数量，以便理解这套系统在不同市场环境下的松紧。

### 开发者与维护者
40. 作为开发者，我想规则引擎是零 I/O 的纯函数，以便书里每条规则都能用单测固定下来。
41. 作为开发者，我想筛选编排接受注入的依赖（日K库 / 快照源 / LLM / 时钟），以便测试永不触网、永不依赖真实时间。
42. 作为开发者，我想全市场扫描不产生逐票扇出，以便不会触发数据源的反爬封禁。
43. 作为开发者，我想复权口径统一为「存不复权 + 因子、指标算在后复权序列」，以便除权不会静默污染均线与缓存。
44. 作为开发者，我想 bootstrap 锚定下载 URL 与 sha256，以便上游数据静默变化能被发现，而不是写入坏数据。
45. 作为开发者，我想新建 ADR-0004 记录反爬实测与数据层决策，以便三个月后不用重新踩一遍封禁。
46. 作为部署者，我想本地库与 bootstrap 产物被 gitignore，以便仓库不会混入数百 MB 构建产物。

## Implementation Decisions

### 模块划分（职责边界）

- **本地日K库（持久层）**：SQLite 单文件，位于 gitignored 的构建产物目录。所有读写经由一个模块，上层只见领域对象。负责：按代码批量读序列、读交易日历、追加当日 bar、更新复权因子、记录元数据（schema 版本、库内最新交易日、bootstrap 的 sha256）。
- **Qlib dump 解析器（bootstrap 专用，纯函数）**：解析 Qlib 二进制格式。格式为**纯 `float32[]`**——元素 0 是日历起始索引，**没有数量字段**，`count = fileSize/4 − 1`。标的清单文件是 `SYMBOL\tSTART\tEND` 且符号**大写**，而特征目录**小写**，必须归一化。字段语义：`raw_不复权价 = close / factor`（open/high/low/vwap 同理）、`raw_手 = volume × factor`、`raw_元 = amount × 1000`。
- **每日增量通道**：腾讯批量快照。单请求可携带约 500 个代码，全市场约 12 个请求。快照字段恰好等同一根日K（今开/最高/最低/收盘/成交量/成交额/换手率）外加**昨收**。
- **指数补齐**：Qlib dump 只含 5 个指数类标的，**不含上证指数与创业板指**，需单独拉取这两个指数的日线历史（各 1 个请求，一次性）。
- **派生指标扩展**：在既有指标体系上增加 MA5/10/20/60/120/144 与**周线重采样**（书 L500：周线 MA20 ≡ 日线 MA100）。
- **短线规则引擎（纯函数，零 I/O）**：输入证据包 → 输出命中项与分档。包含书的四层规则与结构形态检测（缺口、涨停位置、低位 123 结构、下降趋势线、震荡区间、显著高低点）。
- **筛选编排（依赖注入）**：`runScreen(criteria, deps)`，deps = { 日K库, 快照源, chat, now }，形状镜像既有 `runAnalysis(input, deps)`。负责惰性刷新、全市场遍历、漏斗统计、缓存、LLM 复核与降级。
- **HTTP 路由**：新增筛选端点，沿用既有统一错误形状。
- **前端**：顶部模式切换；筛选器控制条；漏斗头；候选卡片（可展开规则清单与扣分项）；大盘门横幅；免责与胜率披露。
- **短线深度分析提示词**：沿用既有六段 persona 结构，但改为书的技术框架（MA100 位置 / 123 结构 / 离场条件 / 仓位），**不产出目标价**。

### 领域模型与接口

新增领域对象（`ScreenerCriteria`、`ScreenerCandidate`、`RuleHit`、`ExitPlan`、`ReferenceResistance`、`MarketGate`、`FunnelCounts`、`ScreenResult`）。`RuleHit` 必须携带 `source: "book" | "offbook"` 与 `bookRef`（如 `"L597"`）以便 UI 溯源。

### API 契约

```

  ?mode=trend|event          默认 trend（均线跟随）
  &strictness=loose|standard|strict   默认 standard
  &boards=main,growth,star,bj         可选，默认 main,growth,star
  &ignoreMarketGate=true|false        默认 false

200 →
{

  dataDate: "YYYY-MM-DD",
  refreshedAt: "ISO8601",
  marketGate: { state: "offense"|"defense"|"empty", indexCode, indexClose, indexMa100, positionAdvice },
  funnel: { universe, afterExclusions, afterHardFilters, shortlisted, reviewed },
  candidates: [ { code, name, price, changePercent, signalTier, ruleHits[], deductions[],
```

错误契约沿用 `{ status, code, message }`。新增一个错误码 **`DATA_NOT_READY`**（503，「本地日K库尚未初始化，请先运行 bootstrap」）——不能复用 `SOURCE_UNAVAILABLE`，因为那是"外部数据源挂了"，而这是"用户还没做初始化"这个可操作的状态。其余复用 `INVALID_INPUT` / `SOURCE_UNAVAILABLE` / `INSUFFICIENT_DATA` / `ANALYSIS_FAILED`。

### 库表结构

存**不复权**价 + **复权因子**；指标一律在后复权序列上计算。

```
instruments(code PK, name, board, listed_start, listed_end, is_live)
bars(code, date, open, high, low, close, volume, amount, adj_factor)   PK(code,date) WITHOUT ROWID
index_bars(code, date, open, high, low, close, volume)                 PK(code,date) WITHOUT ROWID
valuation(code, date, close, pe_ttm, pb_mrq, ps_ttm, board_name)       PK(code,date) WITHOUT ROWID
meta(key PK, value)   -- schema_version / latest_trade_date / bootstrap_sha256
```

`code` 与 `date`（`yyyymmdd` 整数）用 INT + `WITHOUT ROWID` 主键，实测约 70 B/行（6 年全市场约 0.57 GB；同一数据 Parquet zstd 约 0.17 GB，但读写增量与点查不如 SQLite 直接）。

### 数据层决策

- **bootstrap 源**：社区 Qlib dump（每日重建、当日更新、6,163 只含北交所、含复权因子、纯 Node 可解析、约 1–2 分钟完成）。**下载 URL 与 sha256 一并钉死**，校验失败即明确报错，绝不写入。
- **每日增量**：腾讯批量快照，**约 12 请求/天覆盖全市场**。用快照的「昨收」与库内上一交易日不复权收盘比对来**检测除权除息**；检测到则只刷新该票的复权因子（必要时走新浪或腾讯逐票历史重拉该票——每日除权股通常只有几十只）。
- **复权口径（关键）**：`qfq = hfq / K`（K 为每股常数），因此**金叉时点与排序在前复权与后复权下完全相同**；但**前复权不是增量稳定的**——每次除权都会追溯改写全部历史，会静默作废已算好的指标与缓存；**后复权是追加稳定的**。故存不复权 + 因子，指标算在后复权序列上。展示用的涨跌幅直接取数据源提供的官方值，不自行计算。
- **惰性刷新**：点「开始筛选」时先比对库内最新交易日与今天，落后则先跑增量再筛；**无 cron、无后台调度**。首次 bootstrap 是一次性人工步骤，不在请求路径内。
- **估值与行业顺带落地**：按交易日一次请求取全市场的收盘价 + PE/PB/PS + 行业归属，六年约 1,454 个请求（≈12 分钟），兼作对 dump 收盘价的独立交叉校验。
- **裁剪**：默认保留 6 年日线。**按日期裁，绝不按板块裁**（北交所仅占 dump 载荷的 1.4%，删它省不了什么且会造成覆盖缺口）。

### 规则体系

**硬性层（三档相同）**：日K 根数 ≥150（MA144 需要）；剔除 ST/\*ST/退市整理；剔除停牌；剔除一字板（`high == low` 无法成交）；剔除已退市（以 dump 的 `end` 是否等于最新交易日判定）；**禁止打板**（入场价 == 涨停价，书 L1537/L1561）；**涨停后第 2–3 日不追高**（书 L1499/L1521）；北交所默认排除；指标算在后复权序列；涨停判定按板块幅度（主板 10% / 创业板·科创板 20%），优先使用数据源提供的涨停价。

| 缺口宽度系数 | ≥0.5×ATR20 | ≥1.0×ATR20 | ≥1.5×ATR20 |
| 缺口失效窗口 | 3 日 | 3 日 | 3 日 |
| 止损空间上限 | ≤10% | ≤8% | ≤5% |
| 走势流畅度 R² | 不要求 | 不要求 | >0.7 且斜率>0 |
| 允许的信号档 | 全开 | 排除最弱档 | 仅最强三档 |

> 上表的完整依据标注（`书 L####` / 推断项 / `书外` 补丁）见参数表附件 `docs/screener-params.md`；该附件是本表的权威来源，本表在两者冲突时以附件为准。

**书外补丁分两级**：安全类（ST/停牌/退市/微盘市值下限/上市交易日下限/成交额下限/禁止打板的一字板剔除）**默认开**；alpha 类（换手率下限、量比下限、放量大阳线确认）**默认关**，开启时结果中必须同时标 `书外`，使用户能区分"书挑的"与"我们加的"。

**大盘门**：进攻 = 上证指数 > MA100 且 3 个月上涨趋势 → 满仓；防守 = 上证指数 > MA100 但趋势不成立 → 半仓；空仓 = 上证指数 < MA100 → 默认不出票 + 横幅 + 逃生开关。做创业板股时叠加创业板指与 MA100 的关系。最终建议仓位取「大盘门建议」与「书的仓位表」的较小者。

**排序**：不用评分。两个模式各有信号档序（均线跟随：底背离双突破 > 低位123 > 三档入场 > MA20 上穿 > 阻力突破/支撑回踩；事件驱动：涨停+低位123 > 涨停B形态 > 突破性涨停 > 向上突破性缺口 > 持续性缺口），档内依次按「止损空间升序 → 刚突破 MA100 的时点越近越优 → 走势流畅度降序 → 流通市值升序 → 成交额降序」tie-break。换手率与量比**不在默认排序因子中**（它们是关闭的 alpha 补丁）。

### 大模型职责边界

- 单次筛选只调用 **1 次** LLM，用于**同档内复核排序 + 写理由**，**不得引入新候选**。
- 规则命中、分档、止损位、仓位、漏斗计数**全部来自确定性计算，零 LLM 依赖**。
- LLM 缺席或失败 → **照常返回规则结果与排序**，每条标「未经 AI 复核」，响应 `degraded.llmReview = true`，页面提示一次。这与既有 `/api/analyze` 的取舍**刻意不同**（那里 LLM 是主体，失败必须 abstain）——差异需在 ADR-0004 写明。
- 每只候选上的「深度分析」按需触发现有单票分析链路，但使用短线视角的提示词。

### 缓存

复用既有内存缓存的形状与 TTL 机制。缓存键 = (交易日, 模式, 严格度, 板块开关, 大盘门覆盖标志, 库数据指纹)。

### 文档

- 修订 `docs/spec.md` 的 Out of Scope：解禁"全市场数据抓取/自建数据仓储"，并说明其被本规格取代的边界。
- 新增 ADR-0004，记录：三轮实测的反爬时间线（push2 家族持续不可达、域名隔离、封禁从 push2 蔓延到 push2his、重复违规升级）、腾讯批量作为全市场主源、本地库决策、复权口径（为什么不用前复权）、sha256 锚定、无 Python 依赖的 bootstrap。
- 参数表作为 ADR-0004 的附件落盘。

### 实现期发现的两处规则冲突（已完成取舍，记录在此）

**一、书自身的冲突：U1 与「低位涨停」互斥。**
第一章 U1「只买入价格运行在 MA100 均线之上的股票」与第六章「MA100 之下的低位涨停」互斥。
两者若共用基础池，**S10（作者称最强的信号）永远无法触发**——它的定义恰恰要求涨停发生在 MA100 之下。
取舍：**位置类规则（`U-ma100` / `X-ma100Whipsaw` / `U-aboveTrendline` / `U-notRange`）仅均线模式适用**；
事件模式保留股票池、安全补丁与流动性门槛，改用事件专属排除条款把关。
这偏离了 Q14「两者共用 U 层」的原意，**待用户确认**。

**二、禁止打板会剔掉所有事件信号。**
`H-noChaseLimitUp` 剔除任何收盘在涨停价的股票，而事件模式的信号全都发生在涨停日。
书 L1537 禁止的是"在**封板价**买入"这个动作，不是"把涨停股列为候选"（L1545 明说涨停+突破可以买入）。
取舍：该条款**仅均线模式适用**；事件模式改为把这条纪律写进离场计划的失效条件。

## Testing Decisions

**好测试的标准**（沿用本项目既有信条）：只测外部行为（给定输入 → 断言输出与契约），不测实现细节；**所有测试永不触网**；外部依赖用注入的 fake 或录制 fixture；不依赖真实时钟。

## Out of Scope

- **60 分钟级信号**：书里「缺口支撑买入」（不在第一次踩线买、第二次踩线回升买）与「轻仓分批入场」需要 60 分钟 K 线，v1 只做日线可算的规则，这两条留到 v2。
- **题材/龙头层**：书第七章的热点题材与龙头股排序需要板块指数、成分股映射与**分钟级封板时间**；且"龙头"是每日仅 1–3 个名额的强择时信号，塞进出 10 只的筛选器会退化成"每天推那几只连板股"。v2 作为独立「热点」视图更合适。
- **1–100 评分制**：书里没有分值体系，权重会变成无法溯源的解读。改用布尔过滤 + 信号分档。
- **打板与隔日超短**：书把打板（入场价 == 涨停价）与涨停后第 2–3 日追高列为禁止行为，故不提供"隔日超短/打板"模式。
- **定时任务**：不做后端调度，改用惰性刷新。
- **筛选结果持久化**：不做历史筛选记录、不做自选/持仓管理。
- **书的板块/代表股名单**：书中实例全部截至 2018 年 7 月，代表股列表含已退市/更名标的，只作"板块→代表股"映射示例，不采用为股票池。
- **K 线截图 OCR**：书中约 130 张图片中 K 线截图不做 OCR（对提炼规则无增量）；三张纯图片表格已转录。
- 既有的美股扩展、多股对比、情绪数据源等仍在 `docs/spec.md` 的 Out of Scope 内，本规格不变更。

## Further Notes

- **这本书给不了什么**（避免后续误用）：没有量价指标阈值（量比 0 次、均量线/缩量 0 次、换手率仅 3 次且无数值）；没有基本面（市盈率 0 次）；没有资金流字段（北向资金/龙虎榜 0 次）；作者原话「根本就不研究成交量」（L2388）、「最常用的指标是均线，有时会看 MACD 黄白线，其他指标完全不看」（L2386）。
- **作者自己承认的局限**（必须进入 UI 文案，不能藏起来）：系统胜率牛市≈50%、熊市≈30%（L1930）；主张「空仓时间应长于持仓时间」（L2040）；反复强调「这不是百分百」（底背离可二三次背离、123 结构常被止损、缺口可能回补、均线假突破很多）。
- **一处需要记录的事实更正**：调研中途曾判断"东财被自己的探测搞成全局封禁"，实测证明是**按域名隔离**——push2/push2his 持续不可达，而 datacenter-web 正常返回 200。现有应用行情因此一直靠腾讯备源降级运行。这条更正要写进 ADR-0004。
- **bootstrap 的信任边界**：选定的 dump 是第三方社区产物（每日重建）。因此 URL 与 sha256 必须一起钉死并校验，且其字段语义（`raw = close/factor`）来自实测交叉验证而非官方文档。若上游停止维护，降级路径是按交易日走 datacenter-web 拿收盘价（但只有收盘价，无 OHLC）。
- **参数表的审阅状态**：三档参数表与排序优先级已单独成稿待用户审阅；其中流通市值上限阶梯、突破 MA100 的窗口天数、缺口宽度系数、止损空间上限、走势流畅度要求、以及日成交额下限（书中完全没有）属于推断值与工程补丁，是最需要人工确认的部分。
- **发布状态**：本规格应先发布为 GitHub issue 并打 `ready-for-agent` 标签（仓库既有 `scripts/publish-spec.sh` 先例）。当前 `gh` 凭据已失效，发布被阻塞；本地文档先行落盘。
