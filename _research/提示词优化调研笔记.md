## 1. 逐项目拆解

### 1.1 ai-hedge-fund —— 本项目提示词的直接源头

#### 架构

`hedge_fund/signals/llm_agent.py`（172 行）定义了全部机制，**persona 只是一个系统提示词**：

```python
def get_system_prompt(self) -> str:
    """The persona — every subclass must define its voice."""
```

关键契约（见 `llm_agent.py:1-21` 模块 docstring）：

> ```
> Failure contract (locked decisions):
> - Data-layer errors PROPAGATE (fail loud — a broken snapshot must never
>   silently become a neutral view).
> - LLM call/parse failures ABSTAIN: Signal(value=0.0, metadata.abstained=True).
> - Every LLM decision persists its exact prompt + response (via PromptCache),
>   and an unchanged snapshot never pays for a second LLM call.
> ```

**中文解读**：数据层出错要"响亮地失败"，模型层出错才"优雅弃权"——两者绝不混同。这个区分很重要：目前很多实现的失败路径是"出错 → 输出中性"，等于把基础设施故障伪装成投资判断。

同时 `hedge_fund/signals/base.py` 明确划界：alpha model **只形成观点，不做仓位/择时/持有期**。

> ```
> The alpha model only forms a *view*. It does NOT decide position mechanics
> (timing, sizing, holding period) — that's the job of portfolio construction
> and execution. This separation (views vs positions) is deliberate.
> ```

**中文解读**：本项目把"评级 + 目标价 + 时间窗"塞进同一次调用，正是在让观点模型兼职做仓位模型。这是目标价经常留空的结构性原因之一（见第 4 节）。

#### 五个 persona 的共同模板

`hedge_fund/signals/{buffett,graham,munger,lynch,druckenmiller}.py`。以 `buffett.py:21-54` 为样本，结构是：

```
① 角色定位  You are Warren Buffett, evaluating a single company as a
            long-term business owner, not a trader.
② 清单式 CoT  Work through your checklist: 1. Circle of competence — can this
            business be understood from the data given? 2. Competitive moat ...
③ 信号规则  Signal rules: - bullish: ... - bearish: ... - neutral: ...
④ 置信度锚定 Confidence scale (0-100): 90-100 exceptional conviction with strong
            evidence; 70-89 solid conviction; 40-69 mixed; 10-39 weak or speculative.
⑤ 硬规则    Hard rules: - Reason ONLY from the data provided. Treat the most recent
            filing date shown as the present day; ... Do not invent numbers.
            - If the data is insufficient to judge, say so and go neutral.
⑥ JSON-only {"signal": "...", "confidence": <0-100>,
            "reasoning": "<your thesis in Buffett's voice, 2-4 sentences>"}
```

本项目 `prompt.ts:16-60` 已经照搬了这个六段结构。所以**问题不在骨架，在骨架里填的内容**。下面是可以直接补进现有骨架的四件事。

#### 可借鉴点 ①：显式声明数据边界（最关键）

`hedge_fund/signals/druckenmiller.py:56-59`：

> ```
> Hard rules:
> - Reason ONLY from the data provided. ...
> - You have no macro or price-action data here — reason from the
>   fundamentals' trajectory only, and don't pretend otherwise.
> ```

同文件 `:9-11` 的模块 docstring 也写了同样的自白：

> ```
> Honest scope note: this persona currently reasons over the
> fundamentals snapshot only — no macro, rates, or price-action data yet — so
> it hunts for inflections in the fundamentals themselves.
> ```

**中文解读**：不做"你没有数据"的声明时，模型会用**通用财经语料**填补空白——这正是"基本面一节很空泛"的根因：它写的不是这家公司的基本面，而是关于"基本面分析应该看什么"的常识。druckenmiller 的做法是把边界写成第二条硬规则，且明确禁止"pretend otherwise"。

#### 可借鉴点 ②：把"弃权/说不清"变成 persona 的正当结论

`hedge_fund/signals/munger.py:26,35-36,42`：

> ```
> 1. Invert, always invert — what would make this investment fail? Look for
>    deteriorating margins, rising leverage, eroding returns on equity.
> ...
> 5. The too-hard pile — if the numbers don't paint a clear picture, this
>    belongs in the too-hard pile. Say so and go neutral. Most things do.
> ...
> - neutral: the too-hard pile, or great quality at a price you won't pay.
> ...
> 70-89 solid case; 40-69 mixed evidence; 10-39 mostly the too-hard pile.
> ```

**中文解读**：两点。一是 `Invert, always invert` 在**单次调用内**强制反向思考，成本为零。二是"too-hard pile"把"说不清"包装成芒格式的智慧而非能力不足——这比"数据不足请降置信度"有效得多，因为后者暗示模型在扣分。配合 `70-89 solid case; 40-69 mixed evidence; 10-39 mostly the too-hard pile`，低档置信度被重新定义成"这东西本来就该进太难堆"，模型的抗拒感下降。

#### 可借鉴点 ③：数值门限写进 persona

`graham.py:28-31`：

> ```
>    Compare P/E and price-to-book (infer from market cap, EPS, and book value per
>    share) against conservative standards.
>    A P/E far above 15-20 demands extraordinary justification you will
>    rarely grant.
> ```

`lynch.py:28-31`：

> ```
> 2. The PEG test — compare the P/E to the earnings growth rate you can
>    actually see in the numbers. A P/E well below the growth rate is
>    attractive; a P/E far above it means you're paying for a story.
> ```

**中文解读**：给出**具体的数字参照系**（P/E > 15-20 需要非凡理由；PEG 检验）。本项目现在的估值清单只问"是否偏离常态"，而"常态"是什么从未定义——模型只能含糊。注意 lynch 的限定语 "the earnings growth rate you **can actually see in the numbers**"：把门限锚在"手上有的数字"上，而不是幻想中的一致预期。

#### 可借鉴点 ④：派生量在代码里算好，不让模型做算术

`hedge_fund/features/snapshot.py:1-12`：

> ```
> A `FundamentalsSnapshot` is everything an investor agent is allowed to know
> about a company as of a given date: a history of financial metrics ... plus a
> few derived aggregates computed here in Python so the LLM reasons over facts
> instead of re-deriving arithmetic.
> ```

`snapshot.py:58-68` 定义了派生聚合字段：`roe_avg / net_margin_avg / gross_margin_trend / bvps_cagr / debt_to_equity_latest`；`snapshot.py:92-103` 的 `render()` 把它们放在 "Summary:" 块里，再接明细表。

硬门槛（`snapshot.py:26,126-137`）：

> ```python
> # An agent can't say anything defensible about a company with less history
> # than this (one year of ttm rows).
> MIN_PERIODS = 4
> ...
>     if len(metrics) < MIN_PERIODS:
>         raise InsufficientData(...)
> ```

**中文解读**：`MIN_PERIODS` 在**调用 LLM 之前**就拦住数据不足的请求。本项目对应物：K 线不足 60 根、或关键技术指标为 null 时，应有对应门槛（例如拒绝给 `price_target`）。

#### 可借鉴点 ⑤：弃权票不参与合议

`hedge_fund/portfolio/construction.py:38-45`：

> ```
> An abstained signal (metadata.abstained is True — LLM failure or
> insufficient data) is excluded from numerator AND denominator: "no
> opinion" must not masquerade as "opinion: neutral". A non-abstained 0.0
> (e.g. PEAD outside its window) is a real neutral vote and dilutes.
> ```

**中文解读**：**"没有观点"和"中性观点"必须区分**。本项目 5 档里的 `hold` 目前同时承担这两种语义，这是"结论偏保守"的一个隐藏来源：模型不确定时会退到 hold，而 hold 在用户眼里是"中性判断"。建议增加一个显式的 `insufficient_data` 状态（见第 5 节）。

### 1.2 TradingAgents —— 多智能体流水线的完整参考实现

#### 架构与调用次数

`tradingagents/default_config.py:110-111`：

```python
"max_debate_rounds": 1,
"max_risk_discuss_rounds": 1,
```

`tradingagents/graph/conditional_logic.py:59-77` 决定了轮次终止条件：

```python
if (state["investment_debate_state"]["count"] >= 2 * self.max_debate_rounds):
    # 3 rounds of back-and-forth between 2 agents
    return "Research Manager"
...
if (state["risk_debate_state"]["count"] >= 3 * self.max_risk_discuss_rounds):
    # 3 rounds of back-and-forth between 3 agents
    return "Portfolio Manager"
```

**默认配置下的决策层调用次数**（`max_recur_limit: 100`，`default_config.py:112`）：

| 环节 | 节点 | 调用次数 |
|---|---|---|
| 4 个分析师（market / sentiment / news / fundamentals） | ReAct 工具循环 | 各多次（工具循环，`recursion_limit` 上限 100） |
| 多空辩论 | Bull Researcher + Bear Researcher | 2 × `max_debate_rounds` = **2** |
| 研究经理裁决 | Research Manager | **1** |
| 交易员 | Trader | **1** |
| 风控辩论 | Aggressive + Conservative + Neutral | 3 × `max_risk_discuss_rounds` = **3** |
| 组合经理终裁 | Portfolio Manager | **1** |

**决策层合计 8 次结构化调用**，另加 4 个分析师的工具循环。这是"真多轮"的完整成本基线——本项目目前是 1 次。

#### 可借鉴点 ①：schema 字段描述即输出指令

`tradingagents/agents/schemas.py:1-17` 的 docstring 直接阐明这一设计：

> ```
> - Their outputs follow consistent section headers across runs and providers
> - Schema field descriptions become the model's output instructions, freeing
>   the prompt body to focus on context and the rating-scale guidance
> ```

最值得抄的是**置信度的"数据质量锚定"定义**（`schemas.py:304-311`）：

```python
confidence: Literal["low", "medium", "high"] = Field(
    description=(
        "Confidence in the assessment based on data quality and sample size. "
        "Use 'low' when one or more sources returned a placeholder or fewer "
        "than 5 data points; 'medium' when data is present but sparse; "
        "'high' when all three sources returned substantive data."
    ),
)
```

**中文解读**：★★★ 这是整份调研里对"置信度永远 60-70 分"最直接的解药。它的置信度**不来自模型的自我感觉**，而来自**输入的可观测属性**（是否有 placeholder、样本量是否 ≥5）。本项目现在的锚定是"90-100 证据充分且各维度一致 / 70-89 多数维度支持"——"充分""一致"都是主观词，模型无法自证，于是全落在中间档。改成可数条件（例如"K 线 60 根完整 + 全部 12 项指标非空 → 上限 85；有任一关键指标为 null → 上限 55；K 线 < 60 根 → 上限 40"）就能立刻拉开分布。

同一文件 `:292-303` 还给出**数值与档位的绑定表**：

> ```
> "overall_score": ... "Guideline for consistency with overall_band: "
> "Bullish ~6.5–10, Mildly Bullish ~5.5–6.4, Neutral/Mixed ~4.5–5.5, "
> "Mildly Bearish ~3.5–4.4, Bearish ~0–3.4. "
> "Only the 0–10 bounds are enforced."
> ```

**中文解读**：让离散档与连续分数互相约束，且明说哪一层是硬约束（只有 0-10 边界被强制）。这比只给 5 档评级更能逼出区分度。

#### 可借鉴点 ②：击杀"永远 Hold"的显式反偏置句

在提示词正文（`managers/research_manager.py:39`）与 schema 描述（`schemas.py:83-89`）里各写了一遍：

> ```
> Commit to a clear stance whenever the debate's strongest arguments warrant
> one; reserve Hold for situations where the evidence on both sides is
> genuinely balanced.
> ```
>
> ```
> "Reserve Hold for situations where the evidence on both sides is genuinely "
> "balanced; otherwise commit to the side with the stronger arguments."
> ```

**中文解读**：★ 这是一种"反中庸"的显式指令：把 Hold 定义为**需要举证的状态**（你必须证明"两边证据真的均衡"），而不是默认值。本项目的 `hold` 定义是"多空证据接近，或缺乏明确方向"——后半句"缺乏明确方向"是一个几乎无成本的逃生舱。删掉它或加大举证要求即可。

#### 可借鉴点 ③：把结论绑定到"必须指名的证据"

`agents/utils/memory.py`（反思产出）与 `graph/reflection.py:12-25`：

> "Cover in order:\n"
> "1. Was the directional call correct? (cite the alpha figure)\n"
> "2. Which part of the investment thesis held or failed?\n"
> "3. One concrete lesson to apply to the next similar analysis.\n\n"
> "Be specific and terse. Your output will be stored verbatim in a decision log "

`reflect_on_final_decision` 的输入（`reflection.py:47-57`）含 **已实现收益**：

**中文解读**：TradingAgents 的"反思"必须看到结果（T+N 收益/超额），因此它是**延迟的第二次调用**，不是同一次调用里的自我批判。这点很重要：不要在同一次调用里假装反思（见第 2 节）。但"cite the alpha figure"的写法——**结论必须引用一个具体数字**——可以直接搬到"引用具体指标值"上。

#### 可借鉴点 ⑥：情绪分析师的 8 条 best practices（可直接改写成 A股版）

`agents/analysts/sentiment_analyst.py:158-177`（节选）：

> ```
> 1. **Read the StockTwits Bullish/Bearish ratio as a leading retail-sentiment
>    signal.** A 70/30 bullish/bearish split is moderately bullish; ≥90/10 may
>    indicate over-extension and contrarian risk; 50/50 is uncertainty. Sample
>    size matters — base rates on the actual message count, not percentages alone.
> 4. **Distinguish opinion from event.** A news headline ("Nvidia announces $500M
>    Corning deal") is an event; a StockTwits post ("buying NVDA, this is going to
>    moon") is opinion. Both are inputs but should be weighted differently.
> 6. **Be honest about data limits.** If StockTwits returned only a handful of
>    messages, or one or more sources returned an "<unavailable>" placeholder, the
>    sentiment read is less robust — flag this explicitly in the `confidence` field
>    and the narrative. If the sources are silent on a given subreddit, say so.
> 8. **Past sentiment is not predictive.** Frame your conclusions as signal for the
>    trader to weigh alongside fundamentals and technicals, not as a price call.
> ```

数据块用 XML 式定界符包裹（`<start_of_news>...</end_of_news>`，`:145-155`）。

**中文解读**：三条可移植。① 给出了**具体的比例门限**（70/30 温和看多，≥90/10 过度延伸有反向风险）；② **区分"事件"与"观点"并区别赋权**；③ **第 8 条"过去的情绪不具预测性……不要当作价格判断"**——这是给"结论偏保守"的一个正当出口：允许模型明确说"我判断的是信号方向，不是价格"。

### 1.3 FinRobot (`finrobot_equity`) —— "五节报告"结构的成熟版本

#### 架构

`finrobot_equity/core/src/modules/equity_agents/` 下 8 个 agent，每个 = 一段 `instructions` 字符串 + 一个 Pydantic 输出字段，由 `agent_manager.py:29-46` 逐个 `Runner.run(agent, financial_prompt)` 调用（即 8 次 LLM 调用）：

```
tagline / company_overview / investment_overview / valuation_overview /
risks / competitor_analysis / major_takeaways / news_summary
```

这个分工与本项目 `sections:{snapshot, fundamentals, technicals, risks[], conclusion}` 几乎一一对应，因此借鉴价值最高。

#### 可借鉴点 ①：统一的五段式提示词模板

全部 8 个 agent 都使用同一骨架（见 `company_overview_agent.py:5-46`、`risks_agent.py:19-52`、`valuation_overview_agent.py:4-30`）：

```
[ROLE]             角色 + 经验年限 + "你的产出服务于谁"
[INPUT DATA]       明确列出你会收到什么
[ANALYSIS TASKS]   编号任务清单，含子项
[OUTPUT REQUIREMENTS] 字数 + 分节顺序
[FORMATTING RULES] 格式禁令
```

例如 `company_overview_agent.py:24-46`：

> ```
> "[INPUT DATA]\n"
> "You will receive a company name and its stock ticker.\n\n"
> "[ANALYSIS TASKS]\n\n"
> "1.  **Business Model & Strategy:** Deconstruct how the company creates, delivers,
>     and captures value.\n"
> ...
> "[OUTPUT REQUIREMENTS]\n"
> "Produce a structured and concise \"Company Overview\" report of 800-1000 words.
> The report must contain the following sections, in order:\n\n"
> "I.   **Executive Summary:** ...
> ```

**中文解读**：`[INPUT DATA]` 单独成段是很多实现缺的——**把"你会收到什么"写清楚，模型就不会去想象它没收到的东西**。本项目现在的 user prompt 有【数据】块，但 system prompt 里没有对应的 `[INPUT DATA]` 声明来"承认这份数据的边界"。

#### 可借鉴点 ②：★★ 每节字数下限 —— 治"空泛"最直接的一招

| agent | 文件:行 | 字数要求 |
|---|---|---|
| company_overview | `company_overview_agent.py:32` | 800-1000 words |
| risks | `risks_agent.py:37` | 600-800 words |
| valuation_overview | `valuation_overview_agent.py:20` | about 500 words |
| competitor_analysis | `competitor_analysis_agent.py:21` | 500-700 words |
| news_summary | `news_summary_agent.py:35` | 400-600 words |
| investment_overview | `investment_overview_agent.py:29` | approximately 600 words |

对比本项目 `prompt.ts:55-57`：`"fundamentals": "<估值与规模评估，2-4 句>"`。

**中文解读**：★★★ **"2-4 句"和"800-1000 词"是两种数量级的要求。** 一个 2-4 句的槽位，无论提示词写得多好，都不可能产出"不像投研报告"以外的结果——**空泛是 schema 规定的**。这是本项目最廉价、最确定的一处修复点。注意 FinRobot 的字数要求是**带下限的区间**，比"至少 N 字"更有效，因为模型会向区间中值靠拢。

#### 可借鉴点 ③：★★★ "so what" 指令

`major_takeaways_agent.py:4-20` 是整个语料里对"深度感"解释最清楚的一段：

> ```
> "You are a senior equity research analyst creating executive takeaways for
> institutional investors. Given financial data tables in markdown format, create
> strategic insights that go beyond basic data description. Do not include any
> estimation or speculative numbers. Do not have any projections or forecasts."
> ...
> "Revenue Growth: [Analyze the business drivers behind revenue growth - what's
> fueling this growth? Is it sustainable? What does it mean for market position?
> Use specific numbers but focus on the 'why' and 'so what'] "
> ...
> "Focus on: WHY these metrics matter, WHAT they reveal about business quality,
> HOW they compare to peers, and WHAT this means for investors. "
> "Be insightful, not just descriptive. Connect financial metrics to business
> strategy and investment thesis."
> ```

**中文解读**：★★★ 这是"详实"与"有深度"的分界线。`what's fueling this growth? Is it sustainable? What does it mean for market position?` 是一串**追问式的槽位**，把"描述指标"逼成"解释指标"。本项目的 technicals 一节现在能做到"详实准确"，正是因为自然语言里隐含了追问；而 fundamentals 一节没有追问式模板，所以退化成"PE 为 X，PB 为 Y，估值处于合理区间"。

直接把 `WHY / WHAT / HOW / WHAT IT MEANS` 写进 fundamentals 的槽位描述即可。

#### 可借鉴点 ④：估值段的两面强制解释 + 禁止预测

`valuation_overview_agent.py:9-24`：

> ```
> "[ANALYSIS TASKS] ..."
> "4. If the valuation is high, discern whether it reflects high growth expectations,
>     a scarcity premium, or contains a bubble element. If the valuation is low,
>     distinguish whether it is a 'value trap' or an investment opportunity with a
>     margin of safety."
> "5. Comprehensively assess the investment's margin of safety by considering
>     industry characteristics, company competitiveness, and profit outlook."
>
> "[ANALYSIS FRAMEWORK] ..."
> "3. Emphasize the alignment between valuation and fundamentals (such as earnings
>     growth, ROE, industry sentiment), avoiding pure numerical comparisons detached
>     from fundamentals."
>
> "[OUTPUT REQUIREMENTS] ..."
> "Do not include any estimation or speculative numbers. Do not have any projections
> or forecasts."
> ```

**中文解读**：★★ 任务 4 是**只用 PE/PB/市值就能执行的两面解释模板**：高估值 → 是"高增长预期 / 稀缺溢价 / 泡沫"中的哪一种；低估值 → 是"价值陷阱"还是"安全边际机会"。这正是本项目 fundamentals 段现在最缺的：**给定 3 个倍数，唯一能做的有意义的分析就是"这个倍数在说什么"**。

同时注意：FinRobot 的估值 agent **明令禁止任何预测和估计数字**（"Do not include any estimation or speculative numbers. Do not have any projections or forecasts."），连 `major_takeaways_agent.py:7` 和 `tagline_agent.py` 都重复了这条禁令。这是对第 4 节问题的另一种正当回答：**不给目标价，且明说不给的理由是方法论约束，而非能力不足**。

#### 可借鉴点 ⑤：风险分类学 + 收口到"要监控的威胁"

`risks_agent.py:27-41`：

> ```
> "1.  **Risk Identification & Categorization:** Systematically identify potential
>      threats to the business.\n"
> "    * **Market Risks:** Changes in customer demand, macroeconomic headwinds,
>      industry disruption.\n"
> "    * **Competitive Risks:** Price wars, loss of market share, technological
>      obsolescence.\n"
> "    * **Operational Risks:** Supply chain disruptions, execution failures, key
>      personnel risk.\n"
> "    * **Financial Risks:** Debt covenants, cash flow issues, reliance on capital
>      markets.\n"
> "    * **Regulatory & ESG Risks:** New government regulations, litigation,
>      environmental liabilities, reputational damage.\n\n"
> "2.  **Risk Prioritization:** Assess the potential impact of the most significant
>      risks.\n"
> "    * For the top 3-5 risks identified, analyze their potential impact on the
>      company's revenue, profitability, and valuation.\n"
> "    * Evaluate any mitigating factors the company has in place.\n"
> ...
> "II.  **Summary of Core Risks:** A concluding paragraph that highlights the 3-5
>      most critical threats the investment team must monitor."
> ```

**中文解读**：★ 两层结构：先按 5 大类**穷举**（防止只写两条泛泛风险），再**排序取 top 3-5 并评估影响与缓释因素**，最后收口到"最需要监控的 3-5 个威胁"。本项目 `risks: ["...", "...", "..."]` 是扁平字符串数组，没有分类、没有排序、没有"影响 vs 缓释"。

注意最后一句是 "the investment team must **monitor**" —— 风险段的出口是**监控项**，不是免责声明。

#### 可借鉴点 ⑥：论点状态枚举

`investment_overview_agent.py:28-32`：

> ```
> "[OUTPUT REQUIREMENTS]\n"
> "Provide a focused \"Investment Update\" memo of approximately 600 words.
> The structure must be as follows:\n\n"
> "•   **Thesis Status:** (Choose one and bold it: **Thesis Confirmed / Thesis
>     Under Review / Thesis Broken**)\n\n"
> ...
> "•   **Thesis Impact:** A paragraph explaining how the recent developments affect
>     the core investment thesis.\n\n"
> ```

**中文解读**：`Thesis Confirmed / Under Review / Broken` 是一个**三态枚举**，比 5 档评级更直接地表达"我的论点现在处于什么健康度"。它和评级正交（评级回答"买不买"，论点状态回答"我的逻辑还站得住吗"）。

#### 可借鉴点 ⑦：护城河方向枚举

`competitor_analysis_agent.py:17-19`：

> ```
> "2.  **Competitive Moat Assessment:** Evaluate the sustainability of the company's
>      competitive advantages.\n"
> "    * Identify the nature of the company's \"moat\" (e.g., network effects,
>      intangible assets, cost advantages, switching costs).\n"
> "    * Assess the strength and durability of this moat. Is it widening, stable, or
>      narrowing? Provide justification.\n\n"
> ```

**中文解读**：护城河 = 4 类枚举 + `widening / stable / narrowing` 三态 + 必须给理由。在没有财报的情况下，A股的"护城河"可以从**市值排位、换手率、波动率特征**间接推断（大盘股 + 低波动 + 低换手 → 更可能是机构定价的核心资产）。但必须配合第 3 节的"代理指标"改造，否则这一段同样是空话。

#### 一处需要注意的内部矛盾

多个 agent 要求模型联网搜索（`company_overview_agent.py:24`: "Use web searches to gather this information."、`valuation_overview_agent.py:9`: "can use online searches"），同时又禁止估计数字。本项目的场景是**无联网、无财报**，所以应统一走 `[INPUT DATA]` 声明 + 禁令路线，而不是 FinRobot 的联网路线。

另注：`finrobot/agents/prompts.py`（41 行）是 leader/role/order 的组织架构模板（"Reply \"TERMINATE\" in the end"），属于多 agent 调度机制，提示词工艺价值有限，此处略过。

**中文解读**：★★★ 三个要点：

3. `Most factors should be inferred from company related news` —— 每个因子必须能溯源到具体输入，而非通用常识。
4. ★ 最后一句 `The prediction result need to be inferred from your analysis at the end, and thus not appearing as a foundational factor of your analysis` 是**反结论污染**：不许把结论当作推理前提。这是数据构造（先有标签再让模型论证）场景的规则，但其精神对本项目有效——**在 prompt 里明确"结论必须在推理之后得出，不得作为前提"**，可以抑制"先定调再找理由"。

`src/agents/technicals.py` 是**纯量化、无 LLM** 的技术分析 agent（725 行）。其核心模式（`:166-183`、`:472-511`）：

```python
strategy_weights = {
    'trend': 0.30,
    'mean_reversion': 0.25,
    'momentum': 0.25,
    'volatility': 0.15,
    'stat_arb': 0.05
}

def weighted_signal_combination(signals, weights):
    signal_values = {'bullish': 1, 'neutral': 0, 'bearish': -1}
    weighted_sum = 0
    total_confidence = 0
    for strategy, signal in signals.items():
        numeric_signal = signal_values[signal['signal']]
        weight = weights[strategy]
        confidence = signal['confidence']
        weighted_sum += numeric_signal * weight * confidence
        total_confidence += weight * confidence
    final_score = weighted_sum / total_confidence if total_confidence > 0 else 0
    if final_score > 0.2:      signal = 'bullish'
    elif final_score < -0.2:   signal = 'bearish'
    else:                      signal = 'neutral'
    return {'signal': signal, 'confidence': abs(final_score)}
```

更简单的一处（`:124-136`）：

```python
bullish_signals = signals.count('bullish')
bearish_signals = signals.count('bearish')
if bullish_signals > bearish_signals:      overall_signal = 'bullish'
elif bearish_signals > bullish_signals:    overall_signal = 'bearish'
else:                                      overall_signal = 'neutral'
# Calculate confidence level based on the proportion of indicators agreeing
total_signals = len(signals)
confidence = max(bullish_signals, bearish_signals) / total_signals
```

**中文解读**：★★★ **置信度 = 一致性比例**（`max(bull, bear) / total`），完全在代码里算，零 LLM 成本、零主观性。本项目已经有 12 项指标，完全可以在 TS 里按同一模式算出一个"指标一致性分"，然后：
- 要么直接用这个分数替代/约束 LLM 报的 confidence；
- 要么把它作为 fact 喂给模型（"12 项指标中 9 项指向同一方向，一致性 75%"），让模型据此选档。

这是解决"永远 60-70 分"最彻底的办法：**把置信度的分母从模型的主观感受换成可数的输入属性**。

### 1.7 dexter —— 投研 memo 的工艺标准（对本项目输出结构最有价值）

dexter 是 `virattt`（ai-hedge-fund 作者）的金融研究 agent（TypeScript）。其价值不在流水线，而在 **`src/skills/` 下的写作规范文件**——这是一份可直接照抄的"什么是像样的投研报告"的定义。

#### 可借鉴点 ①：★★★ 可证伪化的论点条目格式

`src/skills/write-memo/SKILL.md:106-113`：

> ```
> ### `{{thesis_bullets}}`
> 3-5 bullets, each in this format:
> > **[Claim]** — [Evidence with a specific number]. *Wrong if [observable falsifier].*
>
> Example:
> > **Ad-tier reaches 15% of subs by '27** — Q1 disclosed 40M ad-tier subs (+85% YoY) on a
> > 270M base; trajectory implies 15% mix at constant adds. *Wrong if ad-tier ARPU compresses
> > below $8 due to inventory glut.*
>

> without a specific operational metric behind it.
> ```

`src/skills/write-memo/memo-style.md:41-50` 给出好坏对照：

> ```
> Every thesis bullet must be a complete falsifiable claim:
> > **[Specific claim with a number]** — [Evidence with a specific number, ideally citing the
> > data point]. *Wrong if [specific observable would happen].*
>
> Good:
> > **Ad-tier reaches 15% of subs by '27** — Q1 disclosed 40M ad-tier subs (+85% YoY) on a
> > 270M base; trajectory implies 15% mix at constant adds. *Wrong if ad-tier ARPU compresses

> > area going forward.

**中文解读**：★★★ **三段式：主张 + 带数字的证据 + "什么情况下我错了"**。这个格式一举解决两个问题：

2. **反保守**：`*Wrong if ...*` 迫使模型给出可观察的证伪条件，而"给不出证伪条件"恰恰是模棱两可结论的特征。给不出 = 这个论点本身不成立。

> ## Step 3: Build Scenarios
>

> - **Price target** (derived from the above)
> - **Return** vs. current price (with sign)
>

> Memos do not need a "conclusion" section. The header already states the recommendation;
> the thesis bullets state the view; the scenarios state the math. A closing paragraph that
> restates these is padding.
>
> The last section in the body is **Monitoring KPIs** — the specific metrics that confirm or
> kill the thesis. That's the right note to end on: what to watch.
> ```

`SKILL.md:139-142`：

> ```
> ### `{{monitoring_kpis}}`
> 3-5 KPIs to track quarterly. These are the metrics that confirm or kill the thesis — not
> generic ones (revenue growth, EPS) but specific ones tied to your variant view.
> ```

完整 memo 骨架（`SKILL.md:20-31` + `:95-175`）：

```
variant_view (最多 3 句：我们看到了什么、为什么这么认为、为什么市场还没 price in)
→ thesis_bullets (3-5 条，可证伪格式)
→ business_snapshot (4-5 行，禁止公司历史套话)
→ whats_priced_in (当前倍数 + 隐含增长/利润率假设 + 我们的分歧与幅度)
→ scenario_table (Bear/Base/Bull × 概率/增长/利润率/退出倍数/目标价/收益)
→ bull/base/bear_narrative (各一段，bear 必须 steelman)
→ catalysts_table (事件 / 日期 / 预期影响，日期要具体)
→ risks_table (风险 / 缓释 / 触发线)
→ position_management (仓位 / 入场 / 止损)
→ monitoring_kpis (3-5 个，最后一个 section)
```

**中文解读**：★★★ 这直接回答了第 6 节。对比本项目现在的 `sections:{snapshot, fundamentals, technicals, risks[], conclusion}`：

- `conclusion` 是**结构性冗余**——评级和推理已经在顶层字段了，再写一个 conclusion 只会产出"综上所述"。**删掉它，换成 `what_would_change_my_mind` + `monitoring[]`。**
- 缺 `whats_priced_in`（当前价格隐含了什么预期）——这是"专业感"的最大来源，而且**只需要 PE/PB 和区间位置就能写**。
- 缺 `variant_view`（我与共识的分歧），但本项目没有共识数据，可改成 `key_tension`（当前数据里最主要的矛盾点）。
- 缺 `catalysts`，无新闻数据时可用"财报披露日/解禁日"替代（需加数据）。

>

**中文解读**：★★★ 这是**单次调用内的自我批判**——不需要第二次 LLM 调用，只需要在 prompt 里放一个"输出前逐条核对"的清单。注意措辞 `Before rendering, verify every check. If any fail, revise the relevant section` —— 明确要求**先自检再输出**，而不是输出一个自检报告。这是性价比最高的质量控制手段。

**中文解读**：★★ **"如果空头段读起来比多头段弱，就重写"** —— 这一句是"结论偏保守"问题的镜像解药。用户抱怨结论保守，但真正的专业报告应该是**多空都强**、然后由赔率决定。要求 bear case 必须 steelman，会同时提高报告的说服力和评级区分度。

### 问题 1：哪些提示词技巧能显著提升"深度感"与具体性

按**证据强度**排序（越靠前，语料中的实现越完整、越确定）：

| # | 技巧 | 出处（可核查） | 为什么有效 |

### 问题 2：多角色/多轮的结构、调用次数、成本，以及哪种性价比最高

#### 语料中的三种结构

**A. 单次调用内的多视角（成本 1x）**

- 实现：ai-hedge-fund 的 persona 清单（`buffett.py:25-35` 6 条清单）、munger 的 `Invert, always invert`（`munger.py:26`）、FinRobot 的 5 类风险分类学（`risks_agent.py:27-41`）、dexter 的输出前自检 7 条（`SKILL.md:142-153`）。
- 关键点：这些**不是"让模型扮演三个角色然后辩论"**，而是"一个角色按三个透镜依次审视"。语料中**没有任何一个项目成功实现了单次调用内的真实辩论**——原因很直白：同一个上下文里的"多空双方"共享同一套推理，无法产生真正的对抗性。**不要假装辩论。**
- 性价比：★★★ 最高。

**B. 单次调用内的"三情景"替代辩论（成本 1x）**

- 实现：dexter `SKILL.md:72-89` 的 Bear/Base/Bull 情景表，每个情景是**驱动假设 + 概率（合计 100%）+ 目标价 + 收益**，然后算加权收益和赔率。
- 关键点：这不是角色扮演，而是**把不确定性显式建模成三个世界**。它达成了辩论的大部分功能（暴露空头逻辑），却不需要第二次调用，而且产出的是可计算的数字而非文字。
- 性价比：★★★ 最高，且**直接解决目标价留空问题**。

**C. 真多轮（成本 8-10x）**

- TradingAgents（`default_config.py:110-111`，`conditional_logic.py:59-77`）：2 次多空辩论 + 1 次研究经理 + 1 次交易员 + 3 次风控辩论 + 1 次组合经理 = **8 次决策调用**，另加 4 个分析师的 ReAct 工具循环（`max_recur_limit: 100`）。
- A_Share：7 个专业 agent + debate_room + PM（见 `src/agents/` 下 14 个 agent 文件）。
- 关键点：真辩论的收益是真实的（Bull/Bear 各自有独立的上下文和激励方向），但**边际收益主要来自"有一个专门唱反调的角色"**，而不是来自"多轮"。
- 性价比：★★ 最低（除非做长期产品）。

#### 折中方案（本项目的推荐路径）

**两阶段（成本 2x）**：第一次调用产出六节初稿；第二次调用**只看到初稿 + 原始数据**，扮演 bear critic，输出 `{counter_arguments[], thesis_breakers[], data_limits[], suggested_rating}`；再由代码合并（或第三次调用做 judge）。
- 依据：这正是 TradingAgents 多空辩论（`researchers/bear_researcher.py`）的最小可用子集——只保留 bear 一方 + 一个裁决。
- 预期：捕获真辩论 70% 的价值，成本 2-3x。

**三次调用（成本 3x）**：draft → bear critic → judge/revision（第三次看到双方的论点后重写评级与目标价）。这是 TradingAgents 结构的最小压缩版。

#### 反思（reflection）的真相

TradingAgents `graph/reflection.py:12-25` 与 FinMem `puppy/prompts.py:15,31-38` 都表明：**反思必须看到已实现结果**（T+N 收益、超额收益），因此它是**延迟的独立调用**，需要持久化决策日志 + 后续行情回填。
- `tradingagents/agents/utils/memory.py` 实现了这套：`store_decision()`（pending 标记）→ `update_with_outcome()`（回填 raw_return / alpha_return / reflection）→ `get_past_context(ticker, n_same=5, n_cross=3)` 再注入未来的 PM 提示词。
- **结论**：同一次调用内的"反思"只能是**无结果的输出前自检**（dexter 路线）。想在 prompt 里写"请反思你刚才的推理"而不给结果，产出的是表演性文字，不是反思。

### 问题 3：数据贫瘠时如何避免"空泛的基本面段落"

语料给出的 6 种策略，按可移植性排序：

**策略 1（★ 必做）：在提示词里显式声明数据边界**

ai-hedge-fund `druckenmiller.py:56-59`：
> `You have no macro or price-action data here — reason from the fundamentals' trajectory only, and don't pretend otherwise.`

本项目的对应写法：
> `你没有该公司的财务报表数据——没有营收、利润、ROE、毛利率、负债率。不要声称或暗示你知道这些数字，也不要写"需要关注公司盈利能力"这类可以套在任何股票上的句子。`

**策略 2（★ 必做）：把"缺失"本身作为输出的一部分**

- FinGPT `prompt.py:51-56`：缺失时保留块标题并写 `No basic financial reported.`（而不是删掉块）
- A_Share `prompts/portfolio_manager/system.md:94`：`如果某项数据缺失，请在 JSON 中说明"暂无数据"，不要输出英文占位词。`
- A_Share `prompts/macro_news_agent/prompt.md:33`：`key_drivers 与 key_risks 不可为空，可用 ["暂无"] 填充。`

**本项目建议**：新增 `data_limits: string[]` 字段，要求"逐条列出本次分析中因数据缺失而无法得出的结论，以及需要什么数据才能得出"。这让"数据边界"从免责声明变成**有信息量的交付物**。

**策略 3（★★ 核心）：用替代指标代理缺失的基本面**

这是唯一能让 fundamentals 段**有实质内容**的办法。本项目现有输入完全够算出一批真正的"基本面代理量"：

| 代理量 | 计算 | 经济含义 |
|---|---|---|
| **隐含 ROE** | `PB / PE(动)` | 因为 PB/PE = (P/B)/(P/E) = E/B = ROE。**只用两个现成倍数就能反推市场定价隐含的净资产收益率** |
| **隐含净利润** | `总市值 / PE(动)` | 市场定价隐含的盈利水平 |
| **隐含净资产** | `总市值 / PB` | 市场定价隐含的账面价值 |
| **隐含 EPS** | `最新价 / PE(动)` | 与 K 线无关的每股盈利锚 |
| **市销率代理** | 需要营收数据（缺），但可用 `总市值 / 换手率` 的量级做活跃度代理 | — |
| **筹码周转强度** | `换手率` 与 `20日年化波动率` 联合 | 高换手 + 高波动 → 交易驱动；低换手 + 低波动 → 配置驱动 |
| **趋势/波动比** | `20日涨跌幅 / 20日年化波动率` | 类夏普：单位风险换来的趋势收益 |
| **上下行波动不对称** | K 线序列的上行/下行半方差 | 是"稳步上行"还是"暴涨暴跌" |
| **区间位置** | 已有 `区间高低与位置` | 结合 20/60 日涨跌幅判断"趋势中段"还是"区间顶部" |
| **最大回撤** | 60 根 K 线 | 波动特征 |

**依据**：ai-hedge-fund `features/snapshot.py:1-12` 明确"派生聚合在 Python 里算好，让 LLM 推理事实而不是重做算术"；`snapshot.py:58-68` 定义了 5 个派生字段。本项目完全可以在 TS 派生层实现同一件事（见第 3 节 P2 项）。

有了隐含 ROE 等派生量，`fundamentals` 一节就能写出真正有内容的东西：
> "PE 动 X、PB Y，隐含 ROE = PB/PE = Z%。在 A股语境下 Z% 意味着……。由于无财报数据，无法验证这个隐含 ROE 与实际盈利能力的差距，也无法判断其可持续性——这正是本次分析最大的数据缺口。"

**策略 4（★）：让 abstain 成为正当结论，而不是失败**

- ai-hedge-fund `munger.py:35-36`：`The too-hard pile — if the numbers don't paint a clear picture, this belongs in the too-hard pile. Say so and go neutral. Most things do.`
- TradingAgents `schemas.py:307-309`：置信度低档由"有 placeholder / 样本 < 5"定义。
- ai-hedge-fund `portfolio/construction.py:41-45`：`"no opinion" must not masquerade as "opinion: neutral"`。

**本项目建议**：把 5 档评级与"数据充分性"解耦——增加 `abstain` 或用独立的 `data_sufficiency: sufficient | partial | insufficient` 字段，避免"因为没数据所以 hold"污染评级分布。

**策略 5：调用前的数据门槛**

ai-hedge-fund `features/snapshot.py:26,133-137`：`MIN_PERIODS = 4`，不足则 `raise InsufficientData`，**在 LLM 调用之前**。
本项目对应：K 线 < 60 根 / 任一关键指标为 null 时，禁止输出 `price_target`（或直接返回 `insufficient`）。这比"让模型自己决定要不要降置信度"可靠。

**策略 6：禁止"合理估计"**

A_Share `prompts/market_snapshot/system.md:9` 是反面教材（`如果新闻中缺少精确数值，请根据报道做出合理估计`）。本项目不得引入此写法。

**结构性提醒**：以上都是缓解措施。**根治方案是补数据**——仓库根目录已有 `free-stock-api-research.md`，A股免费财报/估值历史源（akshare、baostock、东方财富）可用。见第 3 节 P2-15~18。

### 问题 4：目标价与时间窗

#### 语料中的三种态度

| 态度 | 项目 | 具体写法 |
|---|---|---|
| **可选，允许为空** | TradingAgents `schemas.py:216-228` | `price_target: float \| None = Field(default=None, description="Optional target price in the instrument's quote currency.")`，并容忍 `"N/A"/"None"/"-"` 等字符串被强制转为 `None`（`schemas.py:30,33-36,225-228`） |
| **明令禁止** | FinRobot `valuation_overview_agent.py:24`、`major_takeaways_agent.py:7`、`tagline_agent.py` | `Do not include any estimation or speculative numbers. Do not have any projections or forecasts.` |
| **强制，但必须由情景表推导** | dexter `SKILL.md:72-89` | 三情景 × 驱动假设 × 概率（合计 100%）→ 目标价 → 加权收益 + 赔率 |
| **完全不给** | ai-hedge-fund `base.py:16-18` | Signal 只是 [-1,+1] 的信念值；"does NOT decide position mechanics (timing, sizing, holding period)" |

#### 本项目目标价留空的根因诊断

`backend/src/analysis/prompt.ts:51-52`：
```
  "price_target": <数字或 null>,
  "time_horizon": "<如 '3-6 个月'，或 null>",
```

三个结构性问题：
1. **没有推导路径**。schema 只给了槽位，没给"从什么算出来"。模型看到孤立的可选数字槽位，最省力的答案就是 null。
2. **null 没有代价**。提示词第 6 条清单说"若证据不足，明确说明而不是强行下结论"，配合上面的 null 槽位，等于**明确鼓励留空**。
3. **输入里没有估值锚**。只有当期 PE/PB，没有历史分位、没有同业对比、没有盈利预测 → **任何具体目标价都是编的**。

**诚实的判断**：以现有输入，唯一不是编造的目标价是**技术位**（SMA200、区间上下沿、ATR 倍数）。

#### 推荐方案（按优先级）

**方案 A（首选，只改提示词）**：把"目标价"改造成"有锚的价格区间 + 触发条件"

```json
"valuation_anchor": {
  "type": "technical_level" | "multiple_based" | "insufficient_data",
  "anchor_description": "锚定 SMA200（12.34 元）——当前价距该位 8.2%",
  "price_range": [11.80, 12.60],
  "derivation": "以 SMA200 为中枢，上下各留 1×ATR14（0.40 元）",
  "confidence": "low",
  "what_would_invalidate": "收盘价连续 3 日跌破 SMA50"
},
"time_horizon": {
  "value": "2-3 个月",
  "basis": "回到 SMA200 所需的历史平均修复时间" 
}
```

要点：**允许 `type: insufficient_data`，但要求给出理由**（而不是把 null 当理由）。这样留空从"默认行为"变成"需要论证的结论"。

**方案 B（低成本，只改提示词）**：dexter 三情景的 A股适配版

```json
"scenarios": [
  {"name": "bear", "trigger": "跌破 SMA50 且量能萎缩", "price_bucket": "-8%~-15%", "probability": 30, "driver": "..."},
  {"name": "base", "trigger": "维持区间震荡", "price_bucket": "-3%~+5%", "probability": 45, "driver": "..."},
  {"name": "bull", "trigger": "放量突破区间上沿", "price_bucket": "+8%~+15%", "probability": 25, "driver": "..."}
],
"probability_weighted_return": "+2.1%",
"risk_reward_ratio": 1.4
```

要点：① 概率必须合计 100（可校验）；② 用**分桶**（FinGPT `prompt.py:86-100` 的 11 桶思路）而非精确价；③ **赔率必须显式输出**，若 < 2 就明说"这不是一个好交易"——这比强行给一个乐观目标价诚实得多，也比留空有信息量。

**方案 C（补充，低成本）**：增加 `invalidation_level`（失效位）

TradingAgents `TraderProposal` 同时有 `entry_price` 和 `stop_loss`（`schemas.py:139-150`）。**止损位比目标价更容易从现有数据推导**（区间低点 / SMA50 / 当前价 − 2×ATR14）。建议无论如何都加上这个字段——它天然可推导、天然具体、天然可证伪。

**方案 D（需加数据）**：真正的倍数锚定

需要：PE/PB 的历史分位（近 3-5 年）+ 同行业可比公司 PE/PB。有了这两样，才能写"当前 PE 处于近三年 35% 分位，同业中位数 X，因此合理 PE 区间为 [a,b]，对应目标价 [c,d]"——这才是专业报告的目标价来源。FinRobot `valuation_overview_agent.py:7` 的 `[INPUT DATA]` 正是这么定义的：`"You will receive the company's PE, PB, and PS valuations, as well as its historical PE, PB, and PS valuation series. Valuation data ... for comparable companies in the same industry"`。

### 问题 5：置信度/评分如何锚定才能避免"永远 60-70 分"

七种可组合的机制，从最治本到最辅助：

**机制 1（★★★ 最治本）：置信度由输入属性定义，而非模型自评**

TradingAgents `schemas.py:304-311`：
> `Use 'low' when one or more sources returned a placeholder or fewer than 5 data points; 'medium' when data is present but sparse; 'high' when all three sources returned substantive data.`

本项目改造（关键是**可数**）：
```
confidence 的档位由数据完整性决定，不取决于你对结论的自信程度：
- 全部 12 项指标非空、K 线 ≥ 60 根、无任何 null 字段 → 上限 85
- 有 1-2 项关键指标为"无数据" → 上限 60
- 有 ≥3 项为"无数据"或 K 线 < 60 根 → 上限 40
- 数据本身矛盾（如趋势与动能方向相反）不能提高上限，只能在上述上限内取更低值
```

**机制 2（★★★）：置信度在代码里算，用"指标一致性比例"**

A_Share `src/agents/technicals.py:134-136`：
```python
confidence = max(bullish_signals, bearish_signals) / total_signals
```
以及 `:508-511`：`'confidence': abs(final_score)`。

本项目：12 项指标中，代码只需判断每项的方向倾向（例如 SMA 关系、MACD DIF vs DEA、RSI 区间、20/60 日涨跌幅符号、区间位置、波动率分位），得到 N_bull / N_bear / N_neutral，再算一致性 = max(N_bull, N_bear) / 12。
- 直接作为 `confidence`（或 `confidence` 的上限）；或
- 作为 fact 喂入："【一致性指标】12 项派生指标中 9 项偏多、2 项偏空、1 项中性（一致性 75%）"。

**这是唯一能把置信度从"语言模型的礼貌性中间值"变成"输入的函数"的办法。**

**机制 3（★★）：离散档位与连续分数互相绑定**

- A_Share `prompts/macro_news_agent/prompt.md:22`：`score: 0到100之间的整数，与signal一致（bullish>60, bearish<40, neutral=40-60）`
- A_Share `prompts/sentiment/user.md:9`：`"bullish"(看多，score>0.3)、"bearish"(看空，score<-0.3)`
- TradingAgents `schemas.py:296-302`：`Bullish ~6.5–10, Mildly Bullish ~5.5–6.4, ... Only the 0–10 bounds are enforced.`

本项目：`buy ↔ confidence ≥ 70`、`overweight ↔ 55-69`、`hold ↔ 40-54`、`underweight ↔ 30-39`、`sell ↔ ≤ 25`（示意）。**注意方向**：TradingAgents 的做法是"分数决定档位"，本项目可以反过来用"档位约束分数区间"，但必须绑定，否则两个字段会各自漂移。

**机制 4（★★★）：击杀默认 Hold 的显式反偏置句**

TradingAgents `managers/research_manager.py:39` + `schemas.py:83-89`（两处重复）：
> `Commit to a clear stance whenever the debate's strongest arguments warrant one; reserve Hold for situations where the evidence on both sides is genuinely balanced.`

本项目现在 `prompt.ts:29` 的 hold 定义：
> `hold：多空证据接近，或缺乏明确方向`

**"或缺乏明确方向"是逃生舱，应删除。** 改成：
> `hold：多空证据在数量与强度上均势均力敌（须在 reasoning 中指出双方最强的各一条论据）。若无法指出，则不得给 hold，必须按证据净方向选择。`

**机制 5（★★）：评级由可数条件定义**

A_Share `prompts/portfolio_manager/system.md:31-32`：`≥5个bullish信号 → 强力看多`、`3-4个 → 温和看多`。

本项目：`12 项指标中 ≥8 项同向且无重大反向 → buy`；`5-7 项同向 → overweight/hold`；`≤4 项 → underweight/sell`。**给出可数的门槛后，评级分布自然张开，且人工可复核。**

**机制 6（★★）：把"没有观点"与"中性观点"分开**

ai-hedge-fund `portfolio/construction.py:41-45`：`"no opinion" must not masquerade as "opinion: neutral"`。
本项目：增加 `data_sufficiency: sufficient | partial | insufficient` 独立字段。当 `insufficient` 时，评级本身不参与统计（或单独归一类）。这直接消除"因为没数据所以 hold → 用户读成「中性判断」"的误读。

**机制 7（★）：要求输出可证伪条件**

dexter 的 `*Wrong if ...*` 与 Tripwire。**给不出证伪条件的结论，本质上是不可校准的**。要求模型必须给出"什么数据会推翻我"，可以把"永远 60-70"里的模糊地带暴露出来。

**附加建议（工程层）**：把每次分析的 `rating`、`confidence`、`指标一致性`、`price_target 是否为空` 写进日志，用 20-50 个样本统计分布。**如果 confidence 的标准差 < 8 或众数区间占比 > 50%，就是模式坍缩的信号**，需要进一步收紧锚定规则。dexter 仓库里有 `src/evals/`（`dataset/finance_agent.csv`、`evaluator.ts`、`sampling.ts`）可作为评测框架的参考。

### 问题 6：有没有比"五节报告"更能体现专业性的结构

有。综合 dexter（最完整）、TradingAgents（schema 层）、FinRobot（分节写手）、A_Share（可数化）后，推荐的骨架是 **"结论先行 + 关键假设 + 证伪条件 + 监控指标"**：

```
0. verdict（顶部一行式结论）
   { rating, confidence, data_sufficiency, one_line }
   —— 对应 dexter SKILL.md:172 的 `[TICKER] · [LONG/SHORT] · Target $X (+Y%) · Asymmetry [N.Nx] · [Conviction]`

1. key_tension（当前数据中最主要的矛盾点，2-3 句）
   —— 对应 dexter 的 variant_view（"what we see, why we think it, why the market hasn't
      priced it"）。本项目没有共识数据，改为"数据内部的张力"：
      例："趋势结构偏多（价在 SMA50/200 上方）与位置偏高（区间 92% 分位）互相矛盾。"

2. whats_priced_in（当前价格隐含了什么预期）
   —— 对应 dexter `memo-style.md` 的 `{{whats_priced_in}}`。
      本项目可用纯派生量写：隐含 ROE = PB/PE、隐含 EPS = 价/PE、区间位置、波动率水平。

3. evidence（分维度，每维度含数值引用）
   - valuation_view（估值水平与含义，含隐含 ROE / 隐含 EPS）
   - trend_view（趋势结构，引用 SMA50/200 与偏离度、20/60 日涨跌幅）
   - momentum_view（动能与摆动，引用 MACD DIF/DEA/HIST、RSI14）
   - volatility_view（波动与位置，引用 ATR14/ATR%、20 日年化波动率、区间位置）
   —— 对应 FinRobot 的分节 agent + A_Share 的显式权重（每维度标注权重）

4. thesis_bullets（3-5 条，可证伪格式）
   **[Claim]** —— [带具体数值的证据]。*Wrong if [可观察的证伪条件]。*

5. counter_case（steelman 后的反面论证）
   { argument（一段连贯的话，不是列表）, strength: 1-5, falsifier }

6. scenarios（Bear/Base/Bull）
   每个含 { trigger, probability（合计 100）, price_bucket, driver }
   + probability_weighted_return + risk_reward_ratio
   —— 替代孤立的 price_target / time_horizon

7. data_limits（数据边界，逐条）
   列出因缺数据而无法得出的结论 + 需要什么数据
   —— 对应 ai-hedge-fund druckenmiller 的 scope 声明 + FinGPT 的 "No basic financial reported."

8. thesis_breakers（失效条件表）
   条件 / 可观察指标 / 阈值 / 检查频率
   —— 对应 dexter 的 Tripwire 列

9. monitoring（监控指标，3-5 个，作为最后一个 section）
   指标 / 当前值 / 触发阈值 / 含义
   —— 对应 dexter `memo-style.md:87`："The last section in the body is Monitoring KPIs …
      That's the right note to end on: what to watch."
```

**最重要的三个变化**：

1. **删掉 `conclusion`**。顶层已有 `rating` + `reasoning`，再写 conclusion 只会产出"综上所述，该股票…"。dexter `memo-style.md:82`：`A closing paragraph that restates these is padding.`
2. **把 `risks: string[]` 换成三列表**（风险 / 缓释 / **触发线**）。这是"专业报告"和"AI 报告"最明显的外观差异。
3. **新增 `whats_priced_in`**。这是"专业感"密度最高的一个字段，而且**只用现有的 PE/PB/区间位置就能写**。

另一个值得抄的结构习惯：FinRobot 每个 agent 都自带 `[ROLE]/[INPUT DATA]/[ANALYSIS TASKS]/[OUTPUT REQUIREMENTS]/[FORMATTING RULES]` 五段式，且输出要求里写清了**分节顺序**。本项目可在 system prompt 里加一个 `[数据边界]` 段来对应 `[INPUT DATA]`。

### 一句话总结

> **本项目的问题诊断**：不是 persona 骨架不好（它已经照抄了 ai-hedge-fund 的正确结构），而是
> ① fundamentals 槽位被规定为"2-4 句"，**结构性地决定了它必然空泛**；
> ② 缺少 `[INPUT DATA]` 式的数据边界声明，模型用通用财经常识填空；
> ③ 置信度用主观词锚定而非数据完整性条件，必然收敛到中间档；
> ④ `price_target` 是孤立可选槽位且没有推导路径，`null` 是零代价的默认答案；
> ⑤ `hold` 的定义里有"缺乏明确方向"这个逃生舱；
> ⑥ 顶层已有评级却还要写 `conclusion`，只可能产出套话。
>
> **最高性价比的六件事**：加字数下限与追问式模板 / 加数据边界段与 `data_limits` / 置信度改为数据完整性条件 / 目标价改为"有锚区间或显式声明无法给出" / 删掉 hold 逃生舱与 `conclusion` / 加具名谬误清单与输出前自检。以上全部只改提示词。
